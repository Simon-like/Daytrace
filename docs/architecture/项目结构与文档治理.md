# 项目结构与文档治理

更新：2026-11-02。状态：按用户“项目文档收敛docs，方便Kimi/Codex协作”的要求执行。技术/产品范围不变。

## 一套文档，少量入口

根README负责启动和导航，根AGENTS负责跨工具接手。局部AGENTS只引用docs规则，根最多50行、局部最多30行，避免每处都维护一份项目现状。

```text
apps/、packages/          正式源码，不放项目说明或handoff
content/                 主人未来的Markdown记录，private单独保管
apps/api/fixtures/       合成Markdown测试/演示数据
design/                  原图、图标、HTML原型和生成脚本
ops/                     可执行部署、容器与配置
experiments/             实验源码、fixture及原始证据
scripts/、tests/          工具与测试
docs/
  README.md              人类与Agent共同的文档首页
  context/               最新任务 / 稳定共识 / 上下文模板
  product/               PRD与验收要求
  design/                视觉规范、资产索引；records存交付说明/提示词
  architecture/          架构、ADR、安全与接口契约
  development/           Demo、开发、测试、内容与应用手册
  operations/            CI/CD与运行维护说明
  collaboration/         board、任务卡、交接、评审、模板与规则
  knowledge/             可复用认识与操作经验
  plans/                 实施计划
  project/               决定、进度、阶段报告、证据与迁移清单
  research/、archive/     原始研究和历史材料
  templates/             内容与素材整理模板
```

“项目文档集中”不等于搬动所有.md。网站记录、实验/测试fixture是产品数据，保留原路径和字节。媒体/代码也保留原位，文档链接过去；下载包内自带README可作离线说明，不成为源码里的第二权威源。

## 每件事只认一个来源

| 问题 | 唯一来源 |
| --- | --- |
| 需求、优先级和验收标准 | product/PRD与验收矩阵 |
| 风格和可用资产 | design/视觉风格基线与资产索引 |
| 技术选择及取舍 | architecture/decisions/ |
| 最新用户范围与现场限制 | context/当前工作上下文 |
| 长期共识 | context/项目记忆 |
| 任务owner、依赖、状态 | collaboration/board.json |
| 当前阶段进度 | project/项目进度 |
| 做了什么、有什么证据 | project/reports与collaboration交接/评审 |
| 怎样开发和运维 | development/与operations/ |
| 可复用研发经验 | knowledge/，含来源与适用范围 |

Kimi/Codex不另建各自状态表。不把报告中的旧下一步当最新授权；不把机器自检、原型、真实设备或生产混成同一结论。

## 新增和归档

优先补充已有权威文档。新ADR、研究、计划、阶段报告按职责放目录，不先在源码旁写一份再“以后归档”。handoff按任务ID+owner命名，来源与实际结果明确。

当前上下文每轮覆盖为最新现场；稳定记忆只有共识变化才修改；进度只由集成者更新。旧报告保留当时语境，历史素材目录通过链接标明，不改写成从未失败。

不再为同一文档留下多层跳转stub。移动时修复仓库引用，并在[迁移清单](../project/migrations/2026-11-02-docs.json)记录old→new；Git保留旧版本。外部已发布URL的兼容另行处理，本轮没有发布文档站。

catalog.json只登记权威入口，不把每一份旧交接塞进首页。首页给少量直接入口，完整目录折叠按需展开。

## 校验与协作

`python3 scripts/project_check.py`检查本地链接、catalog、中央台账、知识元数据及版本管理文档的落位；`--write-index`只重建目录生成块。新增散落项目说明会被CI拒绝，Markdown数据与薄AGENTS入口例外。

原子任务脚本始终读取docs/collaboration/board.json，不回退到旧coordination目录。独立worktree需主checkout认领或显式--root；跨设备文件锁不共享，单协调者维护。规则见[协作协议](../collaboration/README.md)。

只检查版本管理的散落文档是为了保留用户未知的未跟踪资产；新文件加入版本管理后同样受门槛约束。未跟踪素材不因此变成可发布资产或已备份内容。
