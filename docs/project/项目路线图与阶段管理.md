# 项目路线图与阶段管理

版本：v1.1。日期：2026-10-30；状态更新：2026-11-03。对应 [PRD](../product/PRD-v1.0.md)。本文件保留阶段门槛与历史排期基线；正式工程和本地Demo已落地，当前执行到M3演示闭环/M4本地预检，未通过完整M4或M5退出门槛。实际进度只看[项目进度](项目进度.md)，技术基线见[全栈架构](../architecture/技术选型与研发路径.md)。

本文件描述阶段依赖，不触发自动执行。最新用户范围和本轮动作以 [当前工作上下文](../context/当前工作上下文.md) 为准。

## 0. 2026-11-03 功能扩充执行里程碑

用户明确后续全力补充功能。以下是最新执行顺序，覆盖此前“先集中做真机验收”的下一优先级，但不取消 M4／M5 退出门槛。每个里程碑继续拆成中央任务卡和可验证纵向切片；每轮实质改动独立提交并推送 `dev`，不虚构固定交付日期。

| 里程碑 | 用户可用增量 | 退出条件 |
| --- | --- | --- |
| F1 主人空间与私密检索 | 真实 OIDC、持久主人会话、公开／全部视图、主人检索、会话失效与退出 | 电脑和手机可登录并找回私密记录；正文、摘要、附件和检索负向测试通过，演示身份不冒充生产身份 |
| F2 内容维护与发布闭环 | 规范化 Markdown／附件批量导入、草稿预览、定位校验错误、本地发布／回滚、导出恢复 | 三类内容各完成一次源文件到预览、发布、回滚；失败不覆盖上一可用版本，真实私密内容不入普通 Git |
| F3 记录关联与复做对照 | 手动关联记录、带日期后续补充、跨次菜谱实践对照 | 技术记录可互链、随想保留原认识、菜谱可比较两次实践；关联与补充继承原记录权限 |
| F4 分享与阅读偏好 | 公开 RSS、分享卡／sitemap、字号偏好；暗色模式须经设计验证后单列 | 公开分享准确且不泄露私密数据；偏好在桌面与 H5 可恢复，不损害中文排版和减少动态效果 |
| M4／M5 质量与发布 | 全量 AC／NFR、真机 Safari、性能收敛、生产部署、备份恢复与回滚 | P0 验收和发布恢复演练完成；模拟视口、源码存在或首页可打开均不冒充正式通过 |

执行上以 F1 → F2 → F3 → F4 为主，F1／F2 先补 P0 缺口，F3／F4 是用户已确认方向的后续功能扩充，不提前同时铺开。主工作项仍不超过两个；性能、权限和真机问题在对应功能轮次内尽早验证，不机械拖到最后。

## 1. 排期假设

- 以一个持续投入的开发能力、用户在里程碑提供必要反馈为估算基线，按工作日计，不假定用户全职参与。
- 示例启动日为 2026-11-02，约 20 个有效工作日；日期用于建立顺序与检查点，不是已确认交付承诺。
- 实际启动、资源、设备或账户变化后重排后续日期，保留原基线和变化原因。未解决依赖不能靠并行增加 Agent 数量掩盖。
- 本计划不创建定时任务或后台执行。每轮实际工作结束更新看板与报告。
- 六个阶段门槛：M0 立项，M1 可运行排版/响应式/动效切片，M2 内容与权限，M3 完整展示，M4 验证，M5 发布维护。

## 3. 阶段任务、责任与报告

### M0：先让立项可评审

- 产物负责人：产品梳理者；用户判断方向和范围。
- 工作：确认 D+手写方向；明确展示优先、移动、Markdown、私密和不做事项；把每项 P0 需求映射到测试与阶段。
- 报告：[M0 立项报告](reports/M0-立项报告-2026-10-30.md)。
- 当前状态：立项文档已形成并作为后续范围基线；需求变化按决定记录维护。网站功能状态不在这里重复判断，统一看项目进度。

### M1：优先攻克排版、响应式与动画

- 产物负责人：设计/前端职责；汇总者检查与已确认风格的一致性。
- 交付样张：技术长文、菜谱、多图、短感想、后续补充、页边手写注记，以及标题/列表/代码/表格排版页。
- 交付状态：320/390/768/1440 的运行截图，连续缩放结果，导航/目录/图片查看/复制动效小样，减少动态效果对照。
- 技术决策：内容协议、渲染方式、路由、私密访问、搜索隔离、字体和图片资源处理。已有原型可借鉴，但先检查再复用，不直接当正式工程。
- 报告：阶段报告 + 技术决策记录 + 证据。M1 锁定技术方案后，再建立具备文件、接口和验证细节的工程实施计划；立项阶段不提前编造尚未决定的代码接口。
- 门槛：不能只交整图；不能只跑桌面；不能在鉴权方案未定时将私密内容预编译进公开包。

### M2：先建立可靠的内容边界

- 产物负责人：前端/工程职责，测试职责复核权限。
- 交付：受控目录与依赖、内容样本和校验、页面渲染、鉴权/附件保护、公开索引边界、可重复预览流程。
- 最早进行权限负向测试、畸形 Markdown 与发布失败测试。
- 报告：内容与权限基础报告、协议与错误说明、测试结果。

### M3：形成可实际使用的阅读站点

- 产物负责人：前端/体验职责。
- 交付：首页、全部记录、搜索、分类/标签、三类详情、补充/提醒、关于和失败页；真实页面导航和前后退。
- 每个功能任务绑定 FR/AC 编号、可查看页面与必要测试；按照用户任务验收，而非按组件数量。
- 报告：功能完成度与体验报告、实际截图/录屏、剩余缺陷。

### M4：证据驱动的质量阶段

- 产物负责人：测试职责，开发修复；用户真实手机条件需落实。
- 交付：AC 全量回归、NFR 专项、真实 iPhone Safari 结果、权限负向结果、动效/阅读对照、性能测量。
- 报告：测试环境、通过/失败用例、缺陷、复测、已知限制。仅有模拟截图时本阶段不得标真机完成。

### M5：发布是一个可恢复的过程

- 产物负责人：发布/维护职责；需用户实际账户与发布范围落实。
- 交付：可访问站点、准确的公开内容集合、私密访问、发布版本、备份恢复与回滚记录、维护说明。
- 报告：发布说明、恢复演练、观察清单、v1.1 候选。
- 门槛：没有回滚和恢复验证，不把“成功打开首页”当发布完毕。外部部署按实际授权与账户条件执行。

## 4. 工作项与进度算法

工作项必须具备：编号、关联 FR/AC、目标产物、责任职责、依赖、状态、实际证据、剩余问题。状态统一为“待开始、进行中、待验证、已完成、受阻、暂缓”。

- “已完成”要求产物存在、当前范围的验证完成、说明已更新。
- 阶段状态由退出门槛判断，不把完成文档等同于完成代码。
- 当前只报告阶段状态和 P0 验收通过数/总数，分母固定于当前版本；没有估算依据不写一个总项目百分比。
- 若需要投入进度，则先给工作项估算权重再累计，变更时重算并保留基线；不事后用随意权重美化进度。
- 同时进行的主工作项原则上不超过两个，避免大量半成品；并行贡献者独立交付，由一个汇总者合并。

## 5. 报告机制

每阶段一份报告，使用 [阶段报告模板](阶段报告模板.md)。阶段内如有实质变化，更新 [项目进度](项目进度.md)，包括完成项、当前项、依赖、预测偏差与下一步。

交付物目录示例是未来约定，不表示文件已经存在：

```text
docs/project/reports/阶段编号-主题-日期.md
docs/project/evidence/阶段编号/设备或用例/截图或记录
docs/project/decisions/决策编号-主题.md
```

每份报告突出：这阶段交付了什么、怎么验证、有什么风险、下一步是什么。用户只需看阶段摘要和实际结果；完整证据保留供维护者追溯。

## 6. 变更与风险控制

- 小调整：不改 P0 范围和主要工期的排版/参数变化，直接实现并记录。
- 范围变更：新增功能、推翻内容协议、改变私密策略、换主题或新增付费依赖，先形成变更记录，说明收益、影响需求、工期和替换项，再更新基线。
- 重要依赖超过计划一个工作日未落实时，给出仍可推进的工作和受影响里程碑，不用“全部停住”掩盖可做部分，也不跳过强制验收。
- 用户反馈冲突时以最新明确要求为准，更新记忆和旧方案状态；历史资产不覆盖。
- 当前主要风险：M1 字体/材质成本、M2 私密保护、M3 内容兼容、M4 真机条件、M5 部署/备份。具体登记于 PRD，并在每份阶段报告更新。

## 7. 版本迭代

v1.0：阅读闭环与权限、响应式、动效质量。v1.0.x：缺陷修复与测量后的性能改进。v1.1：根据真实回看与内容维护痛点，在 Skill 导入、菜谱对照、公开作品或偏好设置中选最有价值的一项；不提前承诺同时全部开发。

每次迭代保留用户反馈→需求→改动→验证→发布的证据链，避免重新讨论已经确定的基础方向。
