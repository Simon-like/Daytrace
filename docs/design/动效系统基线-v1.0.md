# 动效系统基线 v1.0

日期：2026-11-02。状态：后续实现遵循的设计基线；参数是 Daytrace 项目建议值，须经参考实现与性能测试确认，不是任何外部团队的官方 token。

本基线补充[视觉风格基线 v1.0](视觉风格基线-v1.0.md)，服务“安静、有温度的私人田野档案”。调研依据见[阅读型产品动效调研](../research/2026-11-02-阅读型产品动效调研.md)。

## 1. 动效的产品职责

动效只承担以下五种职责：

1. **操作反馈**：按下、选中、复制、展开、关闭等操作已经被接收。
2. **状态变化**：加载、成功、失败、可用、禁用等状态发生变化。
3. **空间连续性**：抽屉、弹出层、灯箱与触发对象之间的关系清晰。
4. **层级关系**：临时遮罩、对话框和主内容的前后关系明确。
5. **系统等待**：无法立即完成的操作有可理解的等待状态。

每个动效必须能指出其中至少一种职责。只为“显得高级”“让页面更生动”而存在的效果，不进入实现。

### 非目标

- 不做营销页式滚动叙事、滚动劫持、全文视差或连续装饰动画。
- 不做正文逐段入场、长列表逐项 stagger、路由全页飞舞或大幅回弹。
- 不用动画掩盖慢接口、阻塞渲染或布局不稳定。
- 不为了统一技术栈而给所有组件引入弹簧、JS 每帧更新或动画依赖。

## 2. 体验原则

### 2.1 阅读不等动画

正文标题、段落、代码、表格与图片默认立即可见。路由完成后的主要内容不得先设为透明再等待入场。动画失败、JS 未加载或减少动态效果开启时，内容与操作仍完整可用。

### 2.2 状态先发生，运动随后解释

焦点、选中值、ARIA 状态、结果文本和辅助技术通知按业务时序立即更新，不能等 `animationend`。关闭动画不能延迟 Escape、返回焦点或下一次操作。

### 2.3 小动作表达关系

普通反馈使用颜色或小位移；弹出层以来源方向的 4–8px 位移和透明度表达出现；抽屉可沿自身完整进出屏幕。阅读内容不使用弹性 overshoot。

### 2.4 随时可打断

连续点击、快速开关、动画中 Escape、路由离开和偏好切换都不能造成动画排队、焦点遗失、透明遮罩残留或状态锁死。优先使用可由浏览器自然反向的 transitions，而不是不可中断的串行动画。

### 2.5 输入方式等价

hover 只是增强，不能是发现功能的唯一途径。键盘、指针、触摸和辅助技术得到等价状态；焦点不能随视觉动画落到尚未可操作的内容上。

## 3. 技术架构：CSS 优先，按复杂度升级

| 层级 | 使用条件 | 实现约定 |
| --- | --- | --- |
| L0 静态状态 | 普通路由、正文、列表、焦点与错误文本 | 不加动画；用排版、颜色和状态文本表达 |
| L1 CSS transition | 颜色、简单透明度、小位移、Select、Checkbox、Toast | 使用共享 token 与 Radix `data-state`／原生状态；默认选择 |
| L2 CSS keyframes | 少量进入／退出或循环等待指示 | 必须可取消、可降级；不串联业务逻辑，不用于正文入场 |
| L3 WAAPI | 需要 JS 精确取消、反向、播放控制的原生动画 | 局部封装，处理 `cancel`／`finish`，不逐帧驱动 React state |
| L4 Motion | 直接拖拽、速度继承、可中断弹簧等 CSS／WAAPI 难以表达的交互 | 先写 ADR 与包体评估，再按需加载；不得全站默认引入 |

无头组件继续提供焦点、键盘和状态语义；Daytrace 本地组件只添加统一动效，不把视觉行为散落在页面中。

### 依赖门槛

新增动画依赖前必须记录：解决的问题、CSS／WAAPI 不足、动态加载方式、gzip 增量、服务端渲染影响、减少动态效果和取消行为。UI-001 当前正文脚本实测为 142121 gzip bytes，高于原 81920 bytes 预算；该缺口未解决前，不得以“更丝滑”为由扩大正文依赖。

## 4. 项目动效令牌

以下数值是统一实现起点，不是“越慢越高级”。退出通常短于进入；超过 280ms 的界面过渡必须重新说明必要性。

### 4.1 时长

| 建议 token | 值 | 用途 |
| --- | --- | --- |
| `duration.instant` | `0ms` | 减少动态效果、立即定位、禁用非必要运动 |
| `duration.micro` | `120ms` | Button、Input、Checkbox 的颜色与按压反馈 |
| `duration.control` | `160ms` | 图标、普通控件状态、搜索结果容器反馈 |
| `duration.enter` | `200ms` | 普通弹出内容、标签展开后的内容淡入 |
| `duration.exit` | `140ms` | 普通退出、关闭、消失 |
| `duration.overlay` | `240ms` | 移动导航、灯箱等较大层级变化 |

允许实现时在既定档位内微调：普通展开／结果替换为 180–220ms，复杂层级为 240–280ms；不能在各组件随意增加新时长。

### 4.2 曲线

| 建议 token | 值 | 用途 |
| --- | --- | --- |
| `easing.standard` | `cubic-bezier(0.2, 0, 0, 1)` | 大多数移动与状态过渡 |
| `easing.enter` | `cubic-bezier(0.16, 1, 0.3, 1)` | 已进入视图的弹出层，快速响应后平稳停下 |
| `easing.exit` | `cubic-bezier(0.4, 0, 1, 1)` | 退出与关闭，不在画面里逗留 |
| `easing.linear` | `linear` | 纯透明度、确定进度等不需要加速感的场景 |

同一组件的关联属性使用同一时长与曲线。不得把颜色、位移、透明度拆成彼此等待的动画队列。

### 4.3 位移与缩放

| 建议 token | 值 | 用途 |
| --- | --- | --- |
| `distance.none` | `0px` | 纯颜色／透明度反馈 |
| `distance.micro` | `4px` | 箭头、Toast、轻量结果替换 |
| `distance.popover` | `8px` | Select、目录弹出层 |
| `distance.overlay` | `16px` | 小型对话框或灯箱内容 |

- 普通界面缩放最低为 `0.98`，只用于按压或灯箱等小范围关系，不做夸张 zoom。
- 抽屉可以从屏外移动自身 100%，这是空间连续性的例外，不推广到正文和卡片。
- 不做可见回弹；若后续直接操控确需弹簧，默认 `bounce: 0`，以手势速度连续和无 overshoot 为验收点。

## 5. 属性与渲染规则

### 默认允许

- `transform`：位移、旋转、有限缩放。
- `opacity`：内容、遮罩和状态反馈。
- `color`、`background-color`、`border-color`：仅小面积控件的短过渡；它们仍可能触发绘制，需纳入 trace。

### 默认禁止

- 动画 `top`／`left`／`right`／`bottom`、`width`／`height`、`margin`／`padding`。
- 用动画改变正文字号、行高、栅格列宽或阅读列宽度。
- 大面积 `filter`、`blur`、`box-shadow`、背景位置或持续噪点动画。
- 每帧更新 React state、同步读取布局后写样式形成 forced reflow。
- 预先给大量元素添加 `will-change`。只有 trace 证明确有问题时才局部、短期使用，并在结束后移除。

展开区域的容器尺寸立即稳定，再让内容淡入；不要为了“顺滑”动画 `height: auto`。长列表更新直接完成布局，只对结果容器做短透明度反馈。

## 6. 组件行为矩阵

下表是后续实现的默认契约。无动画不等于无反馈；焦点、颜色和文本始终存在。

| 组件 | 默认动效 | 时长／曲线 | 中断与焦点 | 减少动态效果 |
| --- | --- | --- | --- | --- |
| Button／链接 | 颜色反馈；主按钮可选用 `scale(0.98)` 表达按压，不用弹簧 | micro／standard | 连续点击不排队；焦点环不淡出 | 取消缩放，保留即时颜色与焦点 |
| Input／搜索框 | border、color、焦点环；不让输入面移动 | micro／standard | 输入、清除、聚焦不等待动画 | 即时状态，功能不变 |
| Select | 触发器颜色与 chevron 旋转；内容 `opacity + translateY(4px)` | 内容 enter 180–200ms、exit 120–140ms；enter／exit | 快速开关从当前状态反向；关闭回触发器焦点；选项可立即键盘操作 | 内容即时出现，chevron 不旋转，焦点与选中值不变 |
| Checkbox | 边框／底色与 Indicator 透明度；可用极小缩放但不画复杂路径 | micro／standard | Space 快速切换不排队，状态立即可读 | 即时勾选，不依赖动画识别状态 |
| 标签／折叠区 | 尺寸立即稳定，内容透明度；不动画高度，不逐项 stagger | enter 160–200ms／standard | `aria-expanded` 同步更新；连续展开不锁操作 | 即时展开，保留状态文本 |
| 移动导航 | 抽屉 `transform`，遮罩 `opacity`；背景不动画 blur | enter 240ms、exit 160–180ms；enter／exit | 打开管理焦点与背景滚动；Escape 关闭；关闭回菜单按钮；反向操作可中断 | 抽屉与遮罩即时切换，焦点管理完整 |
| 搜索结果更新 | 状态文本立即更新；结果容器可短淡入，不逐条飞入 | control 160ms／linear 或 standard | 新输入取消旧请求／旧视觉状态；不阻塞阅读与点击 | 即时替换，状态文本仍清楚 |
| 路由切换 | **无全页转场**；保留 shell，页面题名与主要操作区可作一组短入场，正文和列表立即可见 | 题名／操作 200–280ms，最多一个 45ms 组间延迟；enter | 焦点与滚动按导航语义处理，不等动画结束；不逐段、不逐项 stagger | 全部即时可见，无差异 |
| 目录定位 | 显式点击时可用浏览器原生平滑滚动；当前项颜色反馈 | 浏览器控制；颜色 control | 更新 hash／焦点与 `scroll-margin`；不接管滚轮 | `scroll-behavior: auto`，立即定位 |
| 图片灯箱 | 图片 `opacity + scale(0.98→1)`，遮罩仅透明度；不做模糊动画 | enter 240ms、exit 160ms；enter／exit | Escape、关闭按钮、焦点返回与触摸可用；加载失败有文本 | 即时显示／关闭，不缩放 |
| Toast／错误反馈 | 文本与 live region 先更新；非关键 Toast 可 `opacity + translateY(4px)` | enter 180ms、exit 120ms；standard | 不遮挡主要操作；关键错误不自动消失，不靠动画提醒 | 即时状态，文本保持完整 |

循环等待指示只用于无法立即完成且确实需要等待的任务；能用确定进度就不用无限旋转。减少动态效果时改为静态“加载中”文本或确定进度。

## 7. 减少动态效果与静态等价

`prefers-reduced-motion: reduce` 开启时：

- 取消非必要位移、缩放、旋转、弹簧、平滑滚动和循环运动。
- 状态可即时切换；确需保留的纯透明度过渡不得超过 80ms，且不得延迟操作。
- 焦点环、选中图标、文本、颜色、ARIA 状态和错误信息不能同时被移除。
- CSS 组件与 JS／WAAPI／Motion 使用同一偏好来源；JS 还需监听偏好变化并取消正在运行的非必要动画。
- 不用全局 CSS 隐藏正在退出的必要状态，也不以 `display: none` 破坏焦点或辅助技术通知。

减少动态效果不是“简化版功能”。所有任务在静态模式下必须同样完成。

## 8. 性能验收标准

### 8.1 每个参考实现必须交出的证据

1. 正常环境与 **4× CPU throttling** 的 Performance trace，覆盖进入、退出和动画中重复操作。
2. 主线程、长任务、forced reflow、绘制和掉帧检查；不能只交录屏或平均 FPS。
3. 动画相关脚本与依赖体积变化，正文路由单独比较，不与整站平均值混合。
4. 布局稳定性检查：动效不制造非预期 CLS；展开导致的用户预期布局变化也不能挤压或遮盖正文。
5. 键盘、触摸、快速反向、Escape、路由离开和运行中切换减少动态效果的结果。

60Hz 下一帧约 16.7ms 可作为分析参考，但不是单凭平均 FPS 就判定通过。参考实现不得出现由动画引起的 >50ms 长任务或重复 forced reflow；发现掉帧需定位并记录，不得只写“感觉流畅”。

### 8.2 设备与浏览器边界

- Chromium 桌面与移动视口是开发回归，不是 iPhone 真机。
- 首批实现至少覆盖一个窄视口（390px 量级）和桌面视口，并测试触摸／键盘路径。
- WebKit 与真实 iPhone Safari 仍需后续专项；性能节流不能替代真实设备能耗、热状态和触摸体验。

## 9. 组件动效卡与完成定义

新增或修改动效时，在任务报告或组件说明记录以下字段：

| 字段 | 必须回答的问题 |
| --- | --- |
| purpose | 属于五种职责中的哪一种？不做会损失什么？ |
| trigger | hover、press、focus、state、route 还是手势？ |
| duration／easing | 使用哪个共享 token？为什么需要例外？ |
| properties | 是否只使用允许的合成友好属性或小面积颜色？ |
| interruptible | 快速反向、Escape、卸载时如何处理？ |
| accessibility | 键盘、触摸、焦点、live region 是否等价？ |
| reduced-motion | 静态反馈是什么？运行中切换偏好是否生效？ |
| performance | trace、长任务、forced reflow、CLS 和体积证据在哪里？ |

只有代码存在不算完成。没有减少动态效果与性能证据的复杂动效，不应进入后续正式验收。

## 10. 首批参考实现与推广顺序

1. **Select**：验证 Radix `data-state`、短进入／退出、键盘焦点与快速开关。
2. **移动导航**：验证较大空间连续性、遮罩、Escape、背景滚动、焦点返回和触摸。
3. **图片灯箱**：验证图片层级、缩放边界、加载失败、关闭与正文脚本预算。

三者通过后，再把令牌推广到 Button、Input、Checkbox、标签、搜索和 Toast。正文 Markdown 渲染专项必须遵守本基线，但本轮不重写 Markdown，也不宣称已解决正文性能缺口。

## 11. 治理

- 组件默认使用本基线 token；局部新值先说明职责和证据，再决定是否补充令牌。
- 新增弹簧、WAAPI、Motion 或任何持续动画必须单独评审，不能从示例代码顺带引入。
- 视觉评审同时检查“静止是否清楚”，不能只看动画视频。
- 调整本基线须更新调研或实施报告，保留当时参数和验证结果，不把未验证的新值直接写成既成标准。
