# MOTION-001：阅读优先的动效系统与设计准则

用户要求学习优秀产品团队的动效方案，为 Daytrace 制定高性能、流畅丝滑且可长期维护的动效系统，作为后续设计准则。本轮只交付调研、设计基线与验收方法，不直接修改应用、不新增动画依赖。

## 本轮范围

- 调研 Vercel、Chrome/web.dev、Motion、Stripe 等官方或一手资料，区分来源事实、Daytrace 设计建议与未采用方案；无法核实的团队传闻不写成事实。
- 延续“安静、有温度的私人田野档案”，将动效限定于操作反馈、状态变化、空间连续性、层级关系和系统等待，不以营销特效、滚动接管或正文入场阻塞阅读。
- 制定 CSS/WAAPI 优先的技术路线、时长与曲线令牌、弹簧使用边界、组件行为矩阵、减少动态效果规则和性能实测门槛。
- 明确后续参考实现与验证顺序，不冒充已完成真实浏览器性能、iPhone Safari 或生产验收。

## 写入与集成

基于主分支 `1079863` 创建独立 `agent/MOTION-001/motion-system` worktree；只写 board 允许的调研、设计、报告和协作文件。中央 board 只在主 checkout 维护。UI-001 虽已完成执行者自检并登记 done，但其代码尚未提交、推送或集成，不能声称本任务已验证其页面动效。

## 验收

- 每个关键结论有可追溯来源；项目建议不冒充某团队官方参数。
- 基线覆盖 Button、Input、Select、Checkbox、标签展开、移动导航、搜索更新、路由切换、目录定位、图片灯箱和 Toast／错误反馈。
- 明确仅动画合成友好属性、无滚动劫持、正文立即可读、可中断、键盘／触摸等价和减少动态效果回退。
- 后续实现必须提交 Performance trace、布局稳定性与多输入验证；Chromium 视口不得冒充真 iPhone。
- `git diff --check` 与 `python3 scripts/project_check.py` 通过，并留下真实交接和执行者自检。
