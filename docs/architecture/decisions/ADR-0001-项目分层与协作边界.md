# ADR-0001：项目分层与协作边界

- 日期：2026-10-30。
- 状态：accepted，执行者依据用户“构建多Agent协作结构与文档/知识编排”的要求落实。
- 范围：仓库组织，不等于正式框架、部署或付费依赖已获批准。

## 决定

单仓库，预留一个正式应用apps/site；docs、knowledge、content分别负责产品工程文档、可复用研发知识、个人站点内容。保留原型原路径，研究/历史全文归入明确目录并保留旧入口。

中央board是协作状态源，原子认领；各Agent有任务ID、独立写入范围、交接和证据。共享入口、契约、依赖和状态由集成者串行合并。正式并行开发采用独立分支/worktree，队列仍只有一个中央源。

## 代价与不采用方案

不采用所有Agent直接改一个app.js/全局CSS/README的模式，避免覆盖；也不为了并行就拆多个服务和包，避免维护成本先于实际需求。

文件协议不能替代权限系统或跨设备同步，仍需遵守明确任务边界。私密内容不走普通Git提交，因此需要独立备份与部署决策。

## 验证

目录实际存在、旧链接可追溯、中央队列无环、认领/交接状态正确、并发同任务只有一方成功、依赖/隐私路径不越界。具体结果见本轮结构报告。

## 2026-10-30增量修订

用户确认Next.js + NestJS + monorepo，原“预留一个应用”由[ADR-0002](ADR-0002-技术路线候选.md)更新为site/api双应用与contracts/config共享包，待ENGINE创建。本文分层、中央队列和串行集成约定仍有效；上文单应用描述保留为原始决定的历史，不作为当前实施指令。

## 2026-11-03分支策略修订

用户明确要求后续只保留`dev`日常开发分支与`main`稳定集成分支，避免到多个任务工作区查看成果。原“正式并行开发采用独立分支/worktree”停止作为后续指令：任务ID、写入边界和中央board继续保留，但所有新工作统一提交`dev`，`main`只接受明确的`dev → main`合并。既有agent分支保留为历史，不自动删除。
