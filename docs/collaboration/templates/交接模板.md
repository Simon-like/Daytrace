# 任务交接

| 项目 | 填写内容 |
| --- | --- |
| 任务ID / owner / 工具 | owner与board一致，工具为Kimi或Codex |
| 用户授权与范围 | 本次具体要做什么，哪些不在范围 |
| 基线 / 分支 / 提交或PR | 实际值；注明是否已集成/推送/部署 |

## 改了什么

主要文件与行为变化，公共契约/依赖/数据迁移影响；跨模块变更交给谁集成。不复制整份PRD或全部聊天。

## 怎样验证

实际命令、输入/设备/环境、结果、证据路径。未执行就写未执行，源码/本地/托管/生产、合成/真实、视口/真机分开。

## 下一位怎么接

- 尚未完成或存在的风险：
- 下一步最具体的一件事与所需文件：
- 失败如何恢复，哪些现场不能覆盖：

交接完成后用中央脚本submit；自检不冒充独立评审，合并不冒充已部署。正文不包含真实私密材料、凭据或未经允许公开的公司内容。
