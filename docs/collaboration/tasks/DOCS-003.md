# DOCS-003：逐轮提交规约与功能扩充里程碑

用户要求每轮改动都形成提交，并在双端基础体验完成后转向全力补充功能，重新明确后续开发里程碑。

## 范围

- 将“每轮实质改动收尾必须独立提交并推送 `dev`”写入根协作入口与中央协议。
- 保留 `dev`／`main` 双分支模型；提交不等于合并 `main`、部署或验收。
- 按功能纵向切片重排后续里程碑：主人空间、内容维护、记录关联、分享与阅读偏好，再接质量与发布。
- 更新路线图、项目决策、稳定共识、当前工作与项目进度；不虚构日期、完成度或已具备的外部账户条件。

## 基线与写入

基于包含 UI-003 的最新 `dev`，只修改 `AGENTS.md` 与 docs 协作、上下文、项目文档，不改应用代码、API、依赖或生产配置。

## 验收

- 新工作能从一个权威入口理解逐轮提交要求及功能优先级。
- 每个功能里程碑有用户可见交付与退出条件，不把 P0 缺口、P1 增强和发布门槛混为一件事。
- 文档校验通过，交接与自检完成后提交并推送 `dev`。
