## 实际改动

首轮 10px 圆角与轻边框版本被用户明确指出“没咋动、太普通”。21:01 第二轮不是继续微调，而是重新组织搜索与筛选控件：

- 搜索：输入和主按钮合成 62px 的完整“检索台”，统一边框、底部承托和柔影；左侧搜索符号有独立色块，focus 时检索台轻微浮起、符号旋转，清除按钮变为独立圆形动作，加入 Enter 键提示。
- Button：主按钮使用更深档案绿、3px 底部承托和独立圆形箭头；hover 上浮并滑动箭头，active 下沉 2px。次按钮有纸面与底部层次，ghost 保持轻量。
- Select：48px 高、14px 圆角，加入档案页片图标、独立圆形箭头和灰绿底；弹出层改为 16px 圆角、分层阴影、44px 选项，hover 有 2px 横移，选中项带圆形勾选。
- 归档：筛选区为 20px 圆角索引卡，标签按钮带 `#` 符号；保留首轮移除重复横线和增加记录留白的结果。
- 动效：归档结果、搜索结果使用 8px 水平淡入，标签展开反向 8px，Select 6px 水平进出。新增反馈只动 transform、opacity、颜色和阴影，无依赖、无逐项 stagger，保留减少动态效果。

调研来源与取舍见 `docs/research/2026-11-02-灵动检索控件调研.md`。

## 性能边界与失败记录

`motion-performance.mjs` 最终结果为 5／6：

- 正常速度 Select、正常／4 倍 CPU 移动导航与灯箱通过。
- 4 倍 CPU Select 没有掉帧、非预期布局偏移或超过 50ms 的 RunTask，但 PerformanceObserver 记录到一次 52ms 长事件；上一轮为 62ms，均为首次打开附近的 pointerdown 处理。
- 对照 READER-002 同场景，最大 pointerdown 已为 41.593ms，说明该操作原本接近阈值；不能据此把本轮称为性能全通过。
- 尝试用 Radix `forceMount` 预挂载下拉层后，出现 combobox 不可见和页面点击被拦截，18 项功能验收仅 14 项通过。该实验已完整回退，最终功能验收重新达到 18／18，最终代码不包含 `forceMount`。

正文路由必要并已请求 JS gzip 为 141627 bytes，高于 81920 bytes 初始预算；该数据沿用完整阅读页测量，不代表本轮控件新增了 60KB。
