# Markdown 内容库使用手册

更新：2026-11-03。CONTENT-003 已实现服务端渲染、主人内容管理、导入预览、版本发布/回滚和单篇导出。当前可在隔离本地 Demo 使用；真实 OIDC 与生产部署仍按 F1/发布门槛执行。

## 打开与上传

使用 Node 24.18.0、pnpm 11.23.0，在项目根目录启动：

```sh
pnpm dev -- --demo
```

打开 `http://127.0.0.1:3000/owner`，进入演示主人空间，再选“打开内容库”。直接管理地址为 `/owner/content`；H5 主人空间与“关于”页可进入独立移动内容库 `/h5/owner/content`，复用同一内容管理服务。演示模式仅允许本机与合成身份，请用合成资料验证；默认 `pnpm dev` 不自动打开上传权限。

1. 选择一个或多个 `.md` 与附件、整个文件夹或 ZIP；也可拖入文件。目录拖拽不是必备能力，手机可用文件选择或 ZIP。
2. 类型可按文档元数据保留；缺省为技术实践，也可给本批指定技术、菜谱或随想。
3. 选择“整理并预览”。普通 MD 无需手写 YAML：系统生成稳定 ID、别名、时间与附件声明，首个 H1 提取成标题。标准包保留身份、分类、摘要与日期等字段，但导入预览一律是私密草稿。
4. 检查正文、脚注、公式、高亮及附件，切换桌面/手机宽度。更新已有文章时可以对照当前版本。缺图、无效文档头或链接会定位到文章，并阻止整批保存，原内容继续可读。
5. 选择保存私密草稿、保存私密文章或明确公开发布。公开需要第二次确认，保存/发布应用于本批全部文章。保存已有公开文章为草稿会撤下其旧公开版本。

预览在本标签页刷新后可恢复。尚未保存的批次可直接丢弃；已保存的草稿在内容列表按状态筛选。源文件被规范化后从原文章“导出”，可拿回补齐 YAML 的标准内容包。

## 正文与附件

支持普通 Markdown、GFM 表格/任务列表/删除线/脚注，服务端 Shiki 高亮与 KaTeX 公式。未知代码语言保留原文，超过 50KB 的代码块不高亮。正文拒绝 HTML、JSX、脚本和任意嵌入。Mermaid 目前保留代码显示，未运行图表脚本；Obsidian 专有语法未承诺完整兼容。

```text
一次上传/
  first.md
  second.md
  images/photo.png
  files/notes.pdf
```

相对附件可写 `images/photo.png`；同批互链可写 `second.md#观察`，导入器转为稳定记录链接。普通多文件选择丢失目录时，附件文件名唯一才允许匹配；有同名附件请使用文件夹或 ZIP，歧义不会猜测。只有被正文引用或在 attachments 中声明的附件会写入记录；无关文件不自动变成文章附件。

允许图片 PNG/JPEG/WebP/GIF、PDF、UTF-8 TXT，并检查签名/编码。外链图片须另存后随文档上传；不自动下载远程地址。SVG/HTML/MDX 不作为上传内容支持。

实际限制：每批上传文件字节合计 **32 MiB**，ZIP 展开合计 **64 MiB**；最多 **100 篇文章、1000 个文件**，单 MD **2 MiB**，单附件 **20 MiB**。路径最多 512 字符、12 层。ZIP 不接收嵌套压缩包、加密文件、符号链接、路径穿越及异常压缩比。目录/ZIP 文件统一校验，失败不部分提交。

## 整理、更新与版本

内容库按标题/标签查找，按类型、状态、公开范围筛选。每篇可打开主人详情、上传新版、管理、导出。

- **上传新版**：从原记录选择，保留 ID，携带当前 revision；或导入已导出且有 ID/revision 的标准包。过期修订或预览基线有变化会返回冲突，重新载入后再检查，不覆盖新版本。重复导入相同无 ID 原始文件会提示改走上传新版。
- **管理**：修改标题、链接别名、标签、状态和公开范围。ID 不变化，改别名保留旧别名；当前协议最多 16 个 oldSlugs，超限会校验失败，不静默删除旧别名。
- **历史版本**：查看经内容库保存的版本，恢复旧正文会生成一个新修订；当前公开范围保持不变，私密文章不会因回滚自动公开。已归档/草稿仅主人可见。
- **导出**：每篇 ZIP 含 `index.md` 与声明附件，普通 Markdown/YAML 可离站使用。导回同库按更新校验修订号，旧包要通过历史恢复或从原文章上传新版。

## 文件夹与持久化

[Markdown v1](../architecture/contracts/markdown-v1.md)仍为正文协议。扫描根仅接受 `public/<记录目录>/index.md`、`private/<记录目录>/index.md`，分类放 type/tags，不在 public/private 下增加分类层。项目 docs、代码与合成样本不自动发布。

```text
CONTENT_ROOT/
  public/<原记录目录>/index.md    初始源内容（不原地覆盖）
  private/<原记录目录>/index.md
  .daytrace/                     自动生成，整个目录被 Git 忽略
    imports/<批次>/content/      私密预览及批次清单
    snapshots/<版本>/           不可变完整源内容和附件
    current.json                当前已校验版本指针
    write.lock                  写入期间的跨进程排他锁
```

首次发布前保存初始版本，后续在新快照写完并校验后原子切换指针；当前进程同步替换读取快照，重启从指针恢复。公开列表、搜索、HTML/目录和附件来自当前快照；附件响应始终 no-store。切换私密会关闭旧公开 ID、旧别名和附件；公开文章仍引用该记录时会阻止发布并提示先处理关联。

正式 `CONTENT_ROOT` 建议放仓库外的持久卷。不要只备份 public/private：新增内容在 `.daytrace/snapshots`。这是单服务实例的本地持久文件库，不是多副本存储；额外进程写入会触发基线冲突保护，但各实例读取快照同步尚未实现。

## 校验、备份与恢复

```sh
CONTENT_ROOT=/absolute/content-root pnpm content:validate
pnpm test:content
```

校验命令读取当前指针；JSON 结果含总记录数、公开数与快照摘要。恢复时先停内容服务，再把**整个内容根目录**（包括隐藏 `.daytrace`、原 public/private 与附件）恢复到持久卷，保持仅服务账户可读写；启动后重新校验，并抽查主人/访客访问及附件。主人会话数据库是独立备份边界，不在单篇文章导出中。

历史与未丢弃预览目前不会自动清理，应随私密内容一同备份并关注磁盘容量；不在服务运行时手工编辑快照或指针。进程异常退出可能留下 write.lock；核验锁中 PID 对应进程已结束后由维护者移除，系统不自动抢锁。不可变快照没有逐文件 fsync 的掉电耐久保证，不能替代备份或数据库事务。真实私密内容、历史与备份都不进入普通 Git、公开目录或浏览器测试证据。

服务默认无身份时管理端点不注册。Auth0 协议客户端与持久会话已接入，真实账户与生产配置仍需验收；合成会话不是真实身份。本地 Demo 在主站与配置的同主机 H5 端口接受受 CSRF 保护的写入，生产配置仍仅接受配置的公开来源。
