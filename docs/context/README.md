# 上下文入口

这里解决接手时先读什么、哪些结论可靠、现在在做什么，不是另一份PRD。

| 层 | 内容 | 权威来源 | 更新时机 |
| --- | --- | --- | --- |
| 稳定共识 | 用户目标、范围、视觉、明确决定 | PRD、视觉基线、决策记录；项目记忆只做摘要 | 用户确认或范围变化 |
| 当前工作 | 本轮目标、最新指令、已完成、未决、下一步边界 | [当前工作](当前工作上下文.md)；里程碑仍看项目进度 | 用户转向、任务交接或阶段切换 |
| 任务上下文 | 一个任务需要的文件、接口、事实、约束与交付 | 中央任务卡与独立上下文包 | 认领/交接时 |

## 默认阅读顺序

根AGENTS和当前工作 → 项目记忆定位共识 → 已授权任务卡和依赖 → 相关PRD章节/设计/ADR/知识与证据。

发现冲突时，区分最新用户要求、已确认决定、建议、历史报告。不能按文件数量投票或自行补为用户决定。

## 交接与维护

使用 [任务上下文模板](任务上下文模板.md)，独立包放coordination/context/，标明基线日期/提交。写清已做、未做、实际证据、下一步和不能继续假设什么，链接源文件，不粘贴整份聊天。

旧包是当时快照，不能覆盖新的当前工作；记忆与共享记忆只负责检索定位。关键要求最终追溯到用户和权威源文件。

每条规则只有一个权威位置。稳定方法进knowledge，实际进度进project，个人记录进content。每阶段汇总当前工作和接力包，不要求接手者逆向读几十份历史报告，也不把全库一次性注入每个任务。
