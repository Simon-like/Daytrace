# 个人知识与生活站点：MVP 产品需求草案

更新日期：2026-10-30

状态：历史需求收敛草案，保留决策过程。后续以 [产品需求与立项文档 v1.0](../product/PRD-v1.0.md)、[视觉风格基线](../../design/视觉风格基线-v1.0.md)和最新用户反馈为准；未开始正式业务开发。

## 1. 已确认的核心诉求

建立一个有审美、分类清晰的个人站点，沉淀技术实践、生活经验与个人认知。降低记录和复盘的执行成本，让用户愿意时常回来翻阅，看见自己的变化，重温勉励自己的话。

首要价值是服务自己的成长；公开表达与个人 IP 是可承接的用途。

### 已确认的一期边界

- 一期优先展示与阅读；电脑端和移动端同等重要，重点做好 iPhone 浏览器体验。电脑端整理材料，手机直接采集以后扩展。
- 不做原生 iOS 应用；一期不做站内编辑器。
- Markdown 是内容的主要流通和存储载体，图片等附件独立保存并采用可迁移的引用方式。
- 视觉采用温暖、安静、有时间感的生活手记方向；审美、响应式阅读和流畅度是核心质量要求。
- 优先整理已有文字、工作留痕、主动提供的 AI 对话记录与照片。
- 材料不足时先保存，允许以后补充，不以追问和填写完整表单为前提。
- 先做快速、可扩展、可维护的 MVP；复杂 Agent 留待后续学习和迭代。
- 回看重点：过去的自己如何想、如今有什么变化，以及值得常常提醒自己的话。
- 站点公开，同时支持私密记录。

## 2. 三个真实场景

### 技术实践：微前端主子应用配置

输入可能包括任务背景、代码片段、错误信息、AI 对话与修复记录。

目标是还原问题拆解、看代码的入口、排查路径和解决依据，并提炼相关概念与适用场景。不能只生成一篇通用的微前端介绍。

区分实际执行并验证的步骤、对话中的建议、尚未验证的解释；不把 AI 提供过的所有知识都视为用户已经掌握。

### 生活实践：麻婆豆腐

输入可能包括过程照、成品照、教程来源和少量随手描述。

输出个人菜谱：实际材料与用量、备菜、工序、关键注意点、这次效果、下次调整。无法从图片或材料确认的用量、火候、顺序保持缺失，不能编造为用户实践。

教程中的做法与用户实际做法需要可区分；后续再次实践可追加记录。

### 随想与认知：待人接物与自我勉励

输入可以只有一段原话或一个具体事件。

保留个人语气和当时的认识，不强行扩写成长文或通用道理。允许摘选一句话作为自己的提醒，并保留它与原记录的联系。

## 3. 建议的最小使用闭环

1. 用户在电脑上提供材料，并发起一次整理。
2. 用户手工或借助现有 AI 工具整理成 Markdown；轻量 Skill 是后续接入方向，不作为展示 MVP 的上线前提。
3. 不足信息作为待补充项保留；不阻塞保存。
4. 站点加载并展示这些内容，用户可在电脑或手机上回看、搜索。
5. 后来有新实践或想法，通过本地文件或 AI 工具追加带日期的补充，再更新站点。
6. 用户明确选择公开的内容进入公开站点，其余仅在授权范围内访问。

说明：站内编辑明确推迟。站点更新机制需要在开发方案中确定；本地 Markdown 修改后不能假定会自动同步到线上。

## 4. 建议的信息结构

- 首页：最近记录、过往片段、给自己的提醒。
- 技术与实践：以问题和经历组织，支持标签检索。
- 生活与做菜：照片与结构化实践记录结合。
- 随想与认知：短记和长文共存，按时间回看。
- 全部记录：按时间、类别和标签筛选、搜索。
- 关于：简要介绍自己，服务公开访问者。

分类先采用三大类，细分领域用标签表达。AI 可以建议标题、类别与标签，用户可以修改。

以上是页面建议，尚未锁定导航名称、独立页面数量和首页布局。

## 5. 两种访问视角

### 自己访问

可浏览本人有权限的公开与私密内容，看到自己的提醒、待补充记录与后续认识。

### 访客访问

只看到公开内容与公开的个人介绍。公开首页的片段、提醒、搜索结果、标签统计均不能间接暴露私密内容。

### 待确认的默认策略

建议新内容默认私密，由用户明确选择公开。记录状态与可见性分开：一条未完善的随想也可以公开，一篇完整文章也可以私密。

私密必须由实际访问控制或独立存储边界保障；仅隐藏菜单或链接不能实现私密。附件、缩略图和公开构建产物需要遵守相同的可见性边界。具体技术方案待开发方案阶段确定。

## 6. 建议的最小内容能力

- 读取并展示三类 Markdown 记录，支持文字和图片，允许内容不完整。
- 保存时间、标题、类别、标签与来源线索。
- 通过内容元数据声明公开或私密，站点按权限展示；一期不做站内切换控件。
- 搜索、筛选、阅读已有记录；内容修改在站外完成。
- 展示带日期的新实践与新认识，保留原始表达。
- 展示从原记录摘选的个人提醒，可回到原文查看语境；摘选在站外完成。
- 长内容支持快速浏览关键结论，再阅读详细过程。
- 内容和图片能够导出、备份，避免更换站点或 AI 工具时重建全部积累。

提醒暂定位为站内回看，不包含定时通知或自动推送。

## 7. 一期暂不纳入

- 手机分享入口、即时拍照上传和跨设备素材自动同步。
- 站内内容编辑器、富文本工具栏、上传管理和保存表单。
- 自主运行、多轮追问、定时复盘的个人 Agent。
- 自动读取所有历史 AI 会话。
- 复杂知识图谱、智能问答和自动发现认知变化。
- 打卡、积分、连续天数与写作任务。
- 评论、关注和多用户社区。
- 自动公开发布全部生成内容。

## 8. 可维护与扩展原则

- 三种场景共享基本记录结构，各自保留合适的内容模板。
- 整理流程与内容存储、站点展示分开，未来可替换 AI 工具或增加手机入口。
- 原始素材与生成记录保留对应关系；素材存储范围与保留策略需另行确定。
- 一期避免引入不必要的独立服务和复杂流程；技术选择应服从公开、私密和维护成本需求。

## 9. 建议的验收情景

1. 导入一篇微前端实践 Markdown，手机上可清晰阅读长文、目录、代码与宽表格，页面不被撑宽。
2. 导入一份含多张图片、材料和工序的菜谱 Markdown，手机上能快速找到材料、步骤和注意点。
3. 一句话的感想可以独立展示，无需补成长文；元数据标注的提醒可以回链原文。
4. 旧记录能够被找到；本地追加新认识并更新站点后，原有内容和补充日期都可回看。
5. 未授权访客无法通过正文、搜索、图片链接或站点附带数据访问私密内容。
6. 公开与个人视角在桌面、平板和 iPhone 浏览器均可正常阅读；手机采集仍不在一期范围内。不得仅依靠桌面浏览器缩窄窗口验收，需包含真实 iPhone Safari。
7. 可以备份并恢复内容与图片，不依赖一次 AI 对话保管成果。

效果验证：用三个真实场景完成闭环，观察用户是否愿意主动回看与补充。记录数量、文章长度和公开流量不作为首要成功指标。

## 10. 下一步待确认

1. 主题已收敛为 D 档案方向，采用 D² 精修秩序并保留原 D 手写装饰。停止横向主题探索，按新 PRD 推进排版、响应式与动效落地。
2. 新内容默认私密仍是建议，尚未确认。
3. 私密内容是否必须在一期通过手机登录阅读；此前已确认支持私密，本问题仅决定访问与部署方式，不能擅自删去该能力。
4. 实际 iPhone 型号与 iOS/Safari 版本、部署位置、身份验证与站点更新方式，在技术方案阶段确认。

## 11. 移动端阅读与 Markdown 基线

- 正文使用通用 Markdown 与明确列出的 GFM 扩展，元数据采用 YAML frontmatter；frontmatter 是额外约定，不属于通用 Markdown 正文规范。
- 内容不依赖 MDX、站点组件或私有指令才能理解；一篇记录与其相对路径附件可整体迁移。
- 一份源文档适配桌面和手机，不为手机维护第二份内容。
- 正文、标题、链接和行内代码在窄屏自然换行；宽表格在独立容器横向滚动，避免整页横向滚动。
- 代码默认保留缩进并局部横滑；可提供软换行和复制，不用缩小字号换取完整显示。
- 图片按容器布局、提供合适分辨率、预留尺寸；正文图不强制裁切，细节图可放大。首屏关键图与后续图片采用不同加载优先级。
- 桌面目录可放在侧边，手机目录收为可展开入口；锚点跳转不被固定导航遮挡。
- 支持浏览器缩放、横竖屏和安全区；交互不依赖鼠标悬停，动效尊重减少动态效果设置。
- 流畅度验收同时包括加载速度、响应和阅读位置稳定，不能仅凭动画或跑分判断。
- 移动端调研依据与候选渲染方案见《移动端Markdown阅读调研》。

推荐推进顺序：确认产品草案与视觉偏好 → 页面结构和关键页面原型 → 确定存储、权限与部署方案 → 拆解并实现 MVP → 使用真实材料验收。
