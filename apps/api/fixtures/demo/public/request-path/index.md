本篇是概念学习演示。它帮助前端开发者为后端需求建立第一张地图。

## 请求的五个停靠点

1. **入口**：反向代理处理域名、TLS与路径转发。
2. **身份**：后端验证会话，并判断这个人能访问什么。
3. **业务**：服务组织规则，而不是让控制器堆满处理步骤。
4. **数据**：读取文件或数据库，返回有明确含义的结果。
5. **响应**：稳定结构、适当状态码和足以排查问题的关联ID。

## 接口返回了什么

```json
{
  "data": { "title": "一份可重读的记录" },
  "meta": { "requestId": "example-request" }
}
```

## 不要把失败翻译成空列表

空集合意味着请求成功，但没有匹配内容。服务不可用意味着现在无法确认结果。两种情况应该给出不同反馈。

## 一张排查清单

| 问题 | 优先看的证据 |
| --- | --- |
| 请求没到后端 | 代理路径、网络状态 |
| 返回401或403 | 会话与权限规则 |
| 返回500 | requestId对应的后端日志 |
| 数据不完整 | 查询范围与响应契约 |
