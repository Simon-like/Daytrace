# ADR-0002：Next.js + NestJS + pnpm monorepo技术方向

- 日期：2026-10-30更新。
- 状态：accepted（技术方向）；精确版本与生产配置待验证。
- 用户依据：先明确React+Nest与monorepo，再表示“使用next确实好”，要求完善架构与CI/CD文档交由其他Agent研发。
- 决定：Next.js承载React页面，NestJS承载业务/权限/内容访问；monorepo管理；本轮实施基线采用全栈TypeScript与pnpm workspace。

## 原建议如何处理

原Astro优先、Nuxt备选是Agent未讨论草稿，从未被用户接受。现由用户明确生态选择替代，停止横向框架选型。保留本文件路径以兼容历史链接，不再将其标题中的“候选”解释为框架尚未决定。

## 结果与代价

统一语言和接口契约，前后端可协同迭代，后续内容导入和Agent接口有明确位置。相较静态站增加后端、身份、数据备份与两服务维护成本；必须限制重复业务和服务数量。Next负责页面，Nest负责业务授权；普通Markdown继续可导出。

ARCH-001改为固定路线的兼容性/性能/部署验证，不再“先验证Astro再选框架”。ENGINE-001在版本、协议和权限边界有证据后建立正式工程。文档accepted不能冒充安装/性能/真机/生产验收。

## 关联决定与待定项

仓库组织对[ADR-0001](ADR-0001-项目分层与协作边界.md)中“单应用”做增量修订：采用site/api两个应用以及必要共享包，文档/知识/内容分层与单一事实源保持有效。详情见[技术架构](../技术选型与研发路径.md)。

CI/CD采用GitHub Actions的方向、可信构建和同产物晋级见[ADR-0003](ADR-0003-CI-CD与发布治理.md)，这是本轮架构实施决定，不是用户逐项选择托管工具。身份提供商、宿主、仓库套餐、镜像仓库、域名、预算与精确版本待核实。

若调整已确认生态需明确用户反馈或阻塞证据；普通版本升级与配置在兼容测试后按维护流程进行。
