# 主人身份、会话与私密访问边界

日期：2026-10-30。状态：SECURITY-001 推荐方案与可执行模型验证；不是正式应用验收，也未接入真实身份提供商或生产数据。

对应 PRD FR-13、FR-14，验收矩阵 AC-02、AC-04、AC-08、AC-13、AC-14、AC-17 与 NFR-03。实验位于 `experiments/SECURITY-001/`。

## 1. 明确推荐

采用 **Auth0 托管 OIDC 登录 + NestJS 权威主人白名单 + NestJS 服务端不透明会话**。Next.js 只做受控 SSR 会话转发，不拥有第二套身份或权限判断。

- Auth0 只回答“这次 OIDC 登录是谁”，使用 Authorization Code Flow、`state`、`nonce`、PKCE 和服务端 discovery/JWKS 校验；不开放任意注册成为站点主人。
- Nest 用精确 `issuer + subject` 白名单决定唯一主人。邮箱只作显示或排障参考，不能单独作为授权键，也不能因为邮箱相同就合并身份。
- Nest 登录成功后签发 256 bit 随机会话 ID，浏览器只持有该不透明值；数据库只保存 SHA-256 哈希。权限、注销、过期和撤销全部由 Nest 每个请求确认。
- 初期单 Nest 实例使用持久卷上的 SQLite；需要多实例、滚动部署或共享写入前迁移 PostgreSQL。内存会话只允许测试，不能作为生产方案。
- Next 不验证 OIDC token、不根据邮箱放行、不直接读取私密快照；所有私密正文、附件、搜索和索引继续经过 Nest。

推荐原因：主人只有一个，不值得自建密码体系；同时应用会话必须能立即注销和撤销，不能只依赖短期 JWT。Auth0 可替换为其他合规 OIDC 提供商，但 Nest 的白名单、会话和访问边界不变。

## 3. 登录与主人白名单

### 3.1 受信路径

1. 浏览器访问同域 `/api/v1/auth/login?returnTo=...`。
2. Nest 生成随机 `state`、`nonce`、PKCE verifier，写入最长 10 分钟、一次性的登录事务；`returnTo` 只允许站内绝对路径，拒绝 `//`、反斜杠、外部 URL 和控制字符。
3. Nest 重定向到 Auth0，使用 `response_type=code`、query 回调和最小 scope（`openid profile`）；不要把 access token 或 refresh token 放进浏览器。
4. Nest callback 一次性消费事务，校验 `state`、issuer、audience、签名、`exp/iat/azp`（适用时）和 `nonce`。使用维护中的 `openid-client` 等 OIDC 库，不手写 JWT 验签。
5. Nest 用验证后的 `iss + sub` 对照主人白名单。非主人返回通用登录失败，不建立应用会话，不返回私密存在性。
6. 主人登录成功后作废旧会话并轮换会话 ID；OIDC token 默认立即丢弃。未来确需调用提供商 API 时再单独设计加密 token 保管，不在一期隐式保存 refresh token。

Auth0 的 [Authorization Code Flow with PKCE](https://auth0.com/docs/get-started/authentication-and-authorization-flow/authorization-code-flow-with-pkce)说明了一次性 code 和 verifier/challenge 的关系。正式实现采用兼容的机密服务端客户端，不能以实验的合成登录代替这些检查。

### 3.2 白名单变更

- 配置项建议为 `OWNER_IDENTITIES`，元素是精确 `iss`、`sub`；空值、仅邮箱、通配符或无法解析时启动失败。
- 会话保存白名单身份键，不在 Cookie 中保存 `role=owner`。每次会话解析都重新对照当前白名单，移除主人身份后立即拒绝并删除其全部会话。
- 白名单变更是受审计的运维动作。日志只记录变更结果和版本，不记录完整身份资料、OIDC token 或秘密。
- staging、local、production 使用不同提供商 application/client 和会话库；测试 `sub` 不能进入生产白名单。

## 4. Cookie、CSRF 与 Origin

会话 Cookie 固定为：

```text
__Host-daytrace_session=<256-bit-random-base64url>;
Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=28800
```

- 必须无 `Domain`，因此 `__Host-` 前缀、host-only、`Path=/` 和 `Secure` 同时成立。生产仅 HTTPS，在反向代理启用 HSTS；本地测试若用 HTTP，只能验证属性字符串，不能冒充浏览器 HTTPS 验证。
- 服务端绝对有效期建议 8 小时，空闲有效期建议 30 分钟；每次有效请求刷新空闲期限，但不能突破绝对期限。Cookie 的 `Max-Age` 不是权限依据。
- 会话 ID 不进 URL、HTML、RSC payload、客户端配置、localStorage 或日志。数据库哈希只降低数据库泄露后的直接重放风险，不替代传输保护。
- 所有 POST/PUT/PATCH/DELETE 要求精确 HTTPS `Origin` 匹配和 synchronizer CSRF token。`SameSite=Lax` 与 `Sec-Fetch-Site` 是纵深防御，不能代替 token。
- CSRF token 从已认证的 `/api/v1/auth/csrf` 获取，响应 `no-store`；服务端只保存哈希，签发新 token 时轮换。跨站、缺失或错误 token 均返回通用 `CSRF_REJECTED`，不改变会话。
- logout 只用 POST。OIDC callback 是跨站返回的例外，但必须严格校验一次性 `state/nonce/PKCE`，不能按普通 GET 放行。
- 不开放跨域 CORS；响应不能出现允许攻击源的 `Access-Control-Allow-Origin`。`Origin: null`、意外 Origin 和伪造 Host 均失败关闭。

这些属性与 OWASP [Session Management Cheat Sheet](https://owasp.org/www-project-cheat-sheets/cheatsheets/Session_Management_Cheat_Sheet.html)一致；CSRF 仍需独立校验，不能因为 HttpOnly 或 SameSite 而省略。

## 5. 注销、过期、撤销与密钥轮换

| 动作 | 必需行为 | 不能误解为 |
| --- | --- | --- |
| 注销当前会话 | 校验 Origin+CSRF；删除服务端会话；按同名同 Path 属性清除 Cookie；返回 `no-store` | 只清浏览器 Cookie；复制过旧 Cookie 的请求仍可用 |
| 空闲/绝对过期 | 每个受保护请求检查服务端时间；过期删除会话；主人搜索提示重新登录，私密对象继续用通用 404 隐藏存在性 | 只依赖 Cookie 自己过期或前端定时器 |
| 撤销全部会话 | 删除该主人所有会话，或提升持久化 `sessionEpoch` 并每次校验；当前及其他设备立即失效 | 撤销 Auth0 access token 就等于删除应用会话 |
| 白名单移除 | 当前请求即失败，并清理主人会话 | 等 7 天 JWT 自然失效 |
| 提供商 logout | 可作为用户体验步骤，使用受验证的 post-logout 回跳 | 删除 Nest 会话的替代品；免费套餐也没有可依赖的 OIDC back-channel logout |
| 备份恢复 | 默认恢复后作废旧会话，要求重新登录；或恢复完整撤销 tombstone 并验证 | 恢复旧数据库后让已注销会话复活 |

本会话是不透明随机 ID，**不需要应用 JWT 签名密钥**，不要为了“轮换”额外引入一套 JWT。仍需处理：

1. OIDC 提供商签名 key：库按 issuer discovery 和 JWKS `kid` 校验，未知 `kid` 时受控刷新并限制失败；QA 使用真实提供商验证轮换行为。
2. Auth0 client secret：只存 Nest 运行时 secret，轮换在维护窗口进行，先写入新值再做登录验证；若提供商不支持双 secret，不承诺零停机轮换，失败时恢复旧可用配置。
3. TLS 证书：由入口代理自动续期并监控到期；证书和私钥不进入镜像、Git 或测试报告。
4. 若未来新增 Cookie 加密/签名、附件签名 URL 或 token 加密 key，必须有独立 `kid`、active+previous 短暂并存、撤销旧 key 和恢复演练；一期不预先增加这些秘密。

## 6. Next SSR 到 Nest 的受控转发

Next 服务端适配器只能执行类似下面的固定逻辑（示意，不是已集成代码）：

```ts
const session = (await cookies()).get('__Host-daytrace_session');
const response = await fetch(`${API_INTERNAL_ORIGIN}/api/v1/records/${validatedId}`, {
  headers: session ? { cookie: `__Host-daytrace_session=${session.value}` } : {},
  cache: 'no-store',
  redirect: 'manual',
  signal: AbortSignal.timeout(2_000),
});
```

强制约束：

- 内部 origin 来自 Nest 专用服务端变量，路径由固定路由和已校验 ID 组成；禁止通用“转发任意 URL”接口。
- 只提取并重写 `__Host-daytrace_session` 一个 Cookie，不原样转发整段 Cookie，也不转发浏览器 `Authorization`、`Host`、`X-Forwarded-*` 或自定义身份头。
- 私密请求显式 `cache: 'no-store'`，使用 request-time cookies，禁止静态生成、ISR、共享 RSC/HTML 缓存和公共图片优化缓存。Next 官方 [fetch 文档](https://nextjs.org/docs/app/api-reference/functions/fetch)说明 `no-store` 每次请求上游；最终仍须按锁定版本做双会话实测。
- SSR GET 不把上游 `Set-Cookie` 透传到页面，也不把 Cookie 写入 HTML、RSC、错误日志或客户端 env。认证写操作走明确同域 API，不走通用 SSR proxy。
- Nest 不相信 `X-Owner`、`X-User-Email` 或“来自内网”的说法；它只根据有效会话 Cookie 授权。
- 公开 SSR 不转发会话 Cookie，输出必须与身份无关。错误响应与私密响应均 `Cache-Control: private, no-store, max-age=0`，并绕过共享缓存。

## 7. 正文、附件、搜索与缓存隔离

### 7.1 内容与错误

- 只有 `visibility: public` 且 `status: published` 的记录进入公开集合。缺失或未知 visibility 的记录进入隔离校验状态，**公开和主人正常索引都不收录**，直到内容修复，而不是默认私密发布。
- 私密对象直链对访客、过期和撤销会话统一通用 404，避免泄露标题和存在性；主人集合/搜索未认证可返回 401 `AUTH_REQUIRED`，不携带私密元数据。
- 生产错误只有稳定错误码和 requestId；不返回堆栈、磁盘路径、原始 SQL、正文、搜索原词或提供商响应。公开错误也不进入公共缓存。

### 7.2 附件

- 路由只接受稳定 asset ID（例如 1–64 位小写字母数字、`_`、`-`），ID 在 Nest 元数据中映射到受控根目录；拒绝路径、编码分隔符、反斜杠、NUL、`..` 和绝对路径。
- 读取前对元数据给出的候选路径做 `realpath`，确认仍在允许根目录内，防止 symlink 逃逸。流式读取失败关闭，不回退到用户提供的文件名。
- 私密附件只能经 Nest 授权接口，访客统一 404，成功与失败均 `no-store`；不得经公共 CDN、静态目录或 Next 图片优化器。响应使用 `X-Content-Type-Options: nosniff`、受控 MIME 和安全的 Content-Disposition。
- 公开转私密要同时移除公开附件产物和缓存；曾下载的字节无法召回。

### 7.3 搜索

- 从显式内容集合分别构建 public index 与 owner index。公开索引绝不先混入私密再由前端过滤；缺失 visibility 不进入任一正常索引。
- 公开搜索即使收到主人 Cookie，也只查询 public index；主人搜索经 Nest 鉴权后查询独立 owner index，响应 `no-store`。
- Next 不挂载私密快照或 owner index。私密搜索词不写访问日志、分析事件、永久搜索历史或错误正文。
- 索引失败返回明确失败，不能伪装成空结果；公开转私密时重建公开索引并清理旧页面、分享卡、RSS、sitemap 和缓存。

### 7.4 缓存

- 只有明确公开且不依赖身份的 2xx 响应可进入共享缓存，key 包含完整公开 URL；认证、私密、非 2xx 和上游异常一律 bypass。
- `Vary: Cookie` 不是隔离的替代品；私密响应根本不能写入共享缓存。公共缓存命中时也不能夹带主人首页、提醒或统计。
- 注销时清理当前页面私密状态，对 `pageshow`/BFCache 恢复做重新验证；不启用私密离线缓存或 Service Worker 持久化。已发送到设备的字节无法靠注销反向擦除。

## 8. 持久化与运行要求

初期 SQLite 表至少包括：

```text
sessions(token_hash PK, owner_issuer, owner_subject, csrf_hash,
         created_at, last_seen_at, idle_expires_at, absolute_expires_at,
         revoked_at, auth_time, schema_version)
login_transactions(transaction_hash PK, state_hash, nonce_hash,
                   code_verifier, return_to, expires_at, consumed_at)
```

- token 只存哈希；登录事务最多 10 分钟并定期清理。数据库文件位于持久卷，应用外不可公开读取，权限最小化，迁移有版本。
- SQLite 使用适合单实例的 WAL/备份流程；ready 检查必须能访问会话库。进程重启后有效会话应按策略保留，过期/撤销记录不得复活。
- 不让多个 Nest 副本共享本地 SQLite 文件或 NFS 文件来“伪多实例”。多实例前迁移 PostgreSQL，补充连接限制、迁移、备份、恢复和兼容回滚。
- 备份包含会话/登录事务库但与普通内容备份分权保护；恢复默认注销全部会话。搜索索引和缓存可重建，不与权威会话状态混淆。
- 会话清理任务只删除过期事务和会话，不记录 token。安全日志仅保留 requestId、时间、事件码、结果和 release；不记录 Cookie、CSRF、code、token、正文或搜索原词。

## 10. 本实验实际覆盖与 OWASP 对照

实验用两个真实回环 HTTP 服务模拟 Next/Nest，17 组测试覆盖公开与私密正向控制、访客、非主人、Cookie 属性、受控转发、空闲/绝对过期、Origin+CSRF、注销、全部撤销、篡改、session rotation、搜索、附件、路径逃逸、错误和缓存。详见实验交接。

| OWASP 2021 | 本方案对应控制 | 尚需正式验证 |
| --- | --- | --- |
| A01 访问控制 | Nest 每请求授权、白名单、对象 404、独立索引和附件 ID | 正式路由逐端点测试、双实例一致性 |
| A02 加密失败 | HTTPS、Secure Cookie、不自建密码、哈希会话 ID | TLS/HSTS、secret 管理、磁盘/备份加密 |
| A03 注入 | 固定上游、参数化 ID、禁止任意路径 | Markdown 清洗、SQL 参数化、MIME/XSS 测试 |
| A04 不安全设计 | 默认不公开、一次性登录事务、短会话、CSRF、可撤销 | 登录/CSRF/搜索频率限制与资源上限 |
| A05 配置错误 | 启动校验、通用错误、无跨域 CORS、安全缓存头 | 真实代理头、debug 关闭、依赖默认配置审查 |
| A06 组件风险 | 推荐维护中的 OIDC/会话库并锁定版本 | 精确版本、SCA/CVE、升级策略，本实验零依赖不覆盖 |
| A07 认证失败 | OIDC state/nonce/PKCE、白名单、过期、轮换、撤销 | 真实 IdP 登录攻击与提供商 MFA/限流 |
| A08 完整性 | discovery/JWKS、持久化 schema、发布版本化 | artifact/依赖签名、数据库迁移与恢复演练 |
| A09 日志监控 | requestId+事件码，禁止 token/正文/搜索词 | 真实日志采样扫描、告警与留存套餐 |
| A10 SSRF | Next 固定内部 origin 和路径，不接收任意代理 URL | Host/redirect/DNS/代理环境负例；URL 预览不在一期范围 |

## 11. 未验证边界

- 本实验不是实际 Next.js/NestJS 包集成；没有验证框架中间件顺序、RSC 实现、standalone 镜像或具体版本 API。
- 未创建 Auth0 tenant，未执行真实 OIDC state/nonce/PKCE/JWKS、client secret 轮换、提供商 logout、MFA 或账号恢复。
- 内存会话只用于测试；未验证 SQLite/PostgreSQL 重启、迁移、多实例、备份和恢复。
- 未经过真实 HTTPS、浏览器 Cookie 策略、CDN、Service Worker、BFCache 或 iPhone Safari。
- 未做正式 Markdown/HTML 清洗、附件 symlink 自动化、Range/大文件、公共图片优化器或全站构建产物扫描。
- 未做独立安全评审、渗透测试、依赖 CVE 扫描或性能/容量测试。
