## 1. 立项摘要

建设一个以 Markdown 为内容底座、兼顾公开与个人私密阅读的响应式个人站点。围绕技术实践、生活经验、随想与认知三类内容，让已有积累容易找到、读懂、回看并持续补充。

一期重心是展示与阅读。移动中文排版、复杂 Markdown 呈现、浏览器交互与适量动效是产品本体，不能作为桌面页面完成后的补丁。

项目进入产品立项与设计落地阶段，停止继续横向生成主题。采用 D 档案方向，以 D² 精修秩序为主，保留原 D 的手写注记。正式站名、Logo、部署、鉴权和最终技术栈尚未确定。

## 2. 问题、目标与成功判断

### 2.1 当前问题

- 工作中依靠 AI 完成陌生领域任务，做完后缺少可复用的排查与理解路径。
- 做菜等生活实践只消费教程，不保留自己的用量、工序和调整经验。
- 个人感想零散，缺乏回看和对照后续认识的空间。
- 用户愿意积累，但不想承担写完整文章、反复分类和经营后台的成本。

### 2.2 一期目标

1. 同一份 Markdown 在电脑和 iPhone 网页都能舒适阅读。
2. 不完整的小记录也能独立存在，技术、生活、感想有合适的展示方式。
3. 用户容易找到旧记录，看到“当时”与“后来补充”的关系。
4. 公开内容可分享，私密内容有真实访问保护。
5. 内容、附件、展示和未来 AI 整理流程解耦，允许迁移与迭代。

### 2.3 成功指标

| 维度 | 一期验收目标 | 收集方式 |
| --- | --- | --- |
| 可用闭环 | 本地新增/修改 Markdown，经预览与发布后，在手机正常阅读 | 三类样本端到端演示 |
| 找到内容 | 从首页或索引在不超过 3 次主要导航操作内到达已知记录；搜索可按标题、标签、正文检索 | 固定任务观察，不把三次视为所有自由浏览的硬上限 |
| 阅读质量 | 指定设备和内容矩阵无整页横向溢出、遮挡或缺失；核心操作均可触摸完成 | 验收矩阵及真机记录 |
| 访问边界 | 未授权无法取得任何私密正文、图片、搜索索引或摘要 | 权限负向测试 |
| 愿意回看 | 试用两周内用户能举出至少一次主动回看或再次实践的真实例子 | 简短访谈或自述，不强制安装行为追踪 |
| 可维护 | 能完成一次内容回滚和一次内容/附件导出恢复 | 发布与恢复演练 |

两周试用属于上线后的效果观察，不作为“上线前已达成”成绩。流量、篇数和连续打卡不作为一期首要指标。

## 3. 用户与使用情景

### 3.1 角色

- 站点主人：在电脑上整理或借助现有 AI 工具产出材料，在电脑/手机读公开与私密记录。
- 公开访客：阅读主人明确公开的记录、分类、标签和个人介绍。
- 素材贡献者/其他 Agent：在项目外部协助整理、设计和制作素材；不是一期站内账号体系。

### 3.2 核心任务

| 情景 | 进入方式 | 用户期待 |
| --- | --- | --- |
| 再次遇到主子应用配置问题 | 搜索“微前端”“路由”，或标签/旧日期 | 找到当时从哪里看代码、如何排查、哪部分验证过 |
| 再做一次麻婆豆腐 | 手机打开菜谱 | 很快看到材料、工序、注意点和自己的改进 |
| 想了解自己过去的看法 | 时间索引、首页回看片段 | 保留原话，读到之后的认识，而非原文被无痕替换 |
| 需要提醒自己 | 首页“给自己的话” | 少量有来源的个人提醒，能回到具体经历 |
| 把一篇实践分享给朋友 | 公开记录链接 | 对方无需登录即可读，链接稳定，公开预览不夹带私密信息 |
| 路上回看私人感想 | iPhone 浏览器登录个人视图 | 不需要原生 App，登录后可读，退出后不能继续从公共缓存取到内容 |

## 4. 范围与优先级

P0：首个可正式交付版本的必需项。P1：首轮试用后进入 v1.1 的候选，不阻塞首版。范围调整必须记录，不以赶进度为由静默删去手机或私密能力。

### 4.1 P0

- D 系列视觉、有限手写装饰、统一排版与响应式导航。
- 首页、全部记录/时间索引、类别/标签筛选、记录详情、关于、404。
- 三类内容的阅读模板，普通 Markdown、明确支持的扩展和附件处理。
- 标题、标签、正文搜索；公开与个人视图分开检索。
- 长文目录、代码复制、局部横滑、图片细节查看、后退位置恢复。
- 原认识与带日期补充、个人提醒回链。
- 主人登录/退出与私密记录、附件访问保护。
- 站外修改 → 校验 → 本地预览 → 发布 → 回滚的维护闭环。
- 质量验证、访问隔离、错误状态、发布说明和恢复文档。

### 4.2 P1 候选

- 阅读字号/主题偏好、暗色模式；只有验证不会损害主风格时引入。
- 手动关联记录、跨次菜谱实践的专门对照视图。
- 稳定公开 RSS、精细分享卡、公开作品页。
- 轻量整理 Skill 与规范化导入；不作为一期站点可用的前提。

### 4.3 明确不做

站内编辑器与上传后台、原生 iOS App、手机一键采集、自动读取全部会话、多用户协作系统、复杂 Agent、知识图谱、自动问答、社交评论、积分打卡、后台定时复盘、离线私密缓存、重型动效和无依据的个性化推荐。

## 5. 信息架构与页面

| 页面 | 主要内容 | 必须具备的状态 |
| --- | --- | --- |
| 首页 | 主人简述、近期记录、生活片段、少量个人提醒、时间入口 | 有内容、无内容、部分无图、本人/访客 |
| 全部记录/索引 | 按年月分组的记录，类别、标签筛选 | 默认、筛选后、无结果、加载/失败（若涉及请求） |
| 搜索 | 输入、结果、命中摘要、清除与关闭 | 未输入、有结果、无结果、失败；私密检索过期 |
| 技术记录 | 背景、路径、关键结论、验证、代码/表格/图示、补充 | 短/长、无目录、缺图、代码不支持高亮 |
| 生活/菜谱 | 封面可选、材料、工序、注意点、本次效果、下次调整 | 信息不全、无照片、多图、追加实践 |
| 随想 | 原始表达、触发背景可选、日期、后续认识 | 一句话、长文、无补充、有补充 |
| 关于 | 真实个人介绍、可选公开联系渠道 | 无头像或资料未完成时不编造 |
| 主人入口 | 登录、退出、公开/全部切换 | 未登录、登录失败、会话失效、返回原页 |
| 404/访问不可用 | 简短说明、回首页或搜索入口 | 不暴露私密标题、摘要和存在性 |

建议路由使用稳定内容 ID，例如 `/records/<id>/`；展示标题和分类变化不应使旧链接失效。最终路由方案由技术设计落定，必须满足稳定链接、直接访问与浏览器前后退。

## 6. 关键流程

### 6.1 站外内容维护

提供 Markdown 与附件 → 校验元数据/链接/权限声明 → 本地预览三类页面 → 生成或更新站点 → 检查发布结果 → 保留上一可用版本。

本地文件更新不等于线上实时同步。一期必须提供一条有文档、可重复执行的更新路径，不要求用户手工在多个系统复制正文。

内容无法解析、ID 重复、引用不存在或附件越界时，发布校验给出文件与原因；不能静默吞掉记录。旧站仍保持可用，不用半成品覆盖已上线版本。

### 6.2 手机阅读

进入公开/个人视图 → 从首页、筛选或搜索打开记录 → 使用目录、代码、图片 → 返回原列表与位置。入口页与列表状态写入 URL 或可恢复的会话状态，刷新与分享有明确行为。

### 6.3 私密访问

主人登录 → 服务端或受保护入口确认权限 → 读取私密内容与附件 → 会话过期时清除界面中的私密结果并提供重新登录 → 退出后阻止后续请求。认证方式在 M1 锁定，不能以未确定为由交付假登录。

### 6.4 后续补充

在源 Markdown 追加有日期的补充 → 更新站点 → 详情页保留原表达并展示新认识。技术上可以整体替换源文件，但产品不能自动用新观点抹去需要保留的原认识。

## 8. 页面与交互细则

### 8.1 首页与记录列表

- 首页以记录和个人表达为主体，不放与内容无关的大型宣传首屏。
- 主人视图可包含私密记录；公开视图的摘要、数量和时间分布均按可见集合生成。
- 用日期和内容类型支持浏览，标签是辅助组织，不强迫内容进入多层目录。
- 无照片不显示空白大封面；短感想不使用“全文不足”之类负面状态。
- 提醒通过显式来源字段或原记录摘句配置，不自动生成“你的名言”。

### 8.2 搜索与筛选

- 搜索入口在手机不藏于深层设置；打开、输入、清除和关闭都有明确定义。
- 标题精确/近似词命中优先于标签和正文命中，最终排序规则需有固定样本验证。
- 示例检索集：“微前端”“主子应用”“路由”“麻婆豆腐”“豆腐”“允许”“registerMicroApps”。具体样本内容需包含相应词。
- 正文检索先要求文字匹配与合理分词，不做语义搜索承诺。
- 搜索引擎与索引组织在技术设计确定；公开索引不得混入私密文档再由前端过滤。
- 一期不永久保存私密搜索词；加载失败可重试，不把失败当作无结果。

### 8.3 长文、代码与表格

- 标题层级遵循文档结构，目录最多显示三级缩进；更深标题仍可阅读和直接链接。
- 超长英文链接/行内代码允许适当断行，中文禁则与中英混排通过样张检查。
- 代码默认保留缩进并局部横滑，软换行为可选增强；小字号不是解决方案。
- 大表格外层横滑、单元格文本合理换行，有非侵入性的可横滑提示；不隐藏列，也不自动把任意二维表变成卡片。
- 未识别语言仍显示纯代码；不为了高亮下载庞大的客户端语言包。

### 8.4 图片、弹层与手写注记

- 正文图保留原比例，封面可按指定焦点裁切，两者分别定义。
- 放大图可关闭、支持 Escape 与合理焦点返回；不拦截系统缩放，不让背景页继续误操作。
- 内容图允许替代文本和说明；缺图保留说明，不留下无限加载状态。
- 手写内容只放在少量页边短注、日期感注记、自我提醒与后续补充中。
- 手机页边注改为段后注记，不悬浮压在正文上。装饰笔触不能代替所有人都要读懂的关键状态。

## 9. 内容模型与迁移约定

本节是产品所需信息契约，字段名称为 v1 建议，在 M1 内容协议中锁定；不是已经实现的数据库或解析 API。

| 信息 | 规则 |
| --- | --- |
| 稳定 ID | 必填、唯一、不可由标题临时推导；重命名不变 |
| 标题 | 必填；纯文字，不嵌入页面组件 |
| 内容类型 | 技术实践 / 生活经验 / 随想认知；菜谱作为生活展示模板 |
| 日期 | 记录发生或创建日期与更新日期可区分；日期处理统一 Asia/Shanghai；无确切发生时间时不伪造 |
| 可见性 | public/private 显式声明；缺失时不自动公开，校验提示并按安全默认处理；这是立项建议，需在 M1 确认 |
| 发布状态 | draft/published/archived 与可见性独立；草稿不进入正常发布集合 |
| 标签、摘要、封面 | 可选；缺失时有合理展示，不影响记录保存 |
| 补充与提醒 | 补充日期和原记录关联；提醒摘句与来源可追溯 |
| 来源与验证情况 | 可记录教程、外链和“实际验证/待验证”；不自动把 AI 回答视为用户掌握 |

正文使用通用 Markdown，加明确支持的 GFM 扩展；YAML frontmatter 是额外元数据约定。脚注、公式、Mermaid、双链和嵌入组件先不默认为 P0；真实内容出现需求后按变更流程评估。

每条记录建议独立目录，Markdown 与相对路径附件可整体迁移。提供内容格式说明、三类示例、错误示例与批量校验；生成的 HTML、搜索索引、缩略图均可重建，不成为唯一内容源。

内容不依赖特定 AI 工具；是否接入 Skill 与站点是否能读写源文件是两件事。先保障用户能手工维护，再扩展整理自动化。

## 10. 响应式排版要求

以下为项目初始设计规则，不是某个框架的既定断点。

| 可用宽度 | 布局策略 | 必查项 |
| --- | --- | --- |
| 320–374 CSS px | 单列，紧凑导航，辅助信息下移 | 长标题、按钮触摸区、行内代码与多级列表 |
| 375–767 CSS px | 舒适单列阅读，目录展开、注记段后显示 | 图片、菜单、搜索键盘、代码和表格横滑 |
| 768–1023 CSS px | 按内容选择单/双栏；正文不被侧栏挤窄 | 平板横竖屏、目录与内容的阅读顺序 |
| 1024 CSS px 以上 | 档案侧栏、主内容，首页可加生活栏目 | 阅读列宽限制、超宽留白、缩放后重排 |

- 断点按内容是否装得下决定，不能只列设备名称；断点之间也要连续缩放检查。
- iPhone 地址栏展开/收起、横竖屏、安全区、系统字体放大、浏览器缩放均纳入验证。
- 正文以 17–18px 起步，关键移动控制触摸区按约 44×44 CSS px 的项目目标设计。
- 排序与视觉移动不能打乱 DOM 阅读顺序和键盘顺序。
- 不使用整页 `overflow:hidden` 掩盖溢出；真正过宽的代码、表格各自约束。
- 手机导航只保留必要入口，不能把桌面全部横向菜单挤进顶栏。

## 11. 动效需求

动效是对操作的解释与反馈；不是等待时间或表演。以下时长为样例基线，最终通过可运行页面确认。

| 场景 | 初始要求 | 减少动态效果/降级 |
| --- | --- | --- |
| 菜单、目录展开 | 约 140–180ms，清楚表达归属，不卡主线程 | 直接切换或短淡入，不滑动大块画面 |
| 图片查看与关闭 | 约 160–220ms，关闭后恢复原位置 | 直接开关，保留同等可用的焦点和关闭入口 |
| 标签/筛选/搜索反馈 | 及时反馈，避免闪烁；不动画每个结果的高度 | 保持静态布局和明确结果数量/状态 |
| 代码复制 | 按钮文字或图标明确成功/失败，短时间后复原 | 同样有静态文字反馈 |
| 锚点定位 | 目标可见，固定顶栏不遮挡；只在不违背用户偏好时平滑定位 | 即时定位 |
| 页面跳转 | 先保障链接、后退与滚动位置；动画可选，不能成为基础依赖 | 普通浏览器导航始终可用 |
| 手写笔触 | 默认静态；若试验绘制仅短暂一次、不延迟内容 | 始终静态 |

不做惯性滚动接管、持续视差、光标追随、全页大面积模糊、逐段强制入场或无限笔触循环。动画中途连续操作、快速开关、离开页面、失焦与减少动态效果切换都要有确定结果。

## 12. 非功能质量要求

### 12.1 性能与稳定性

公开内容优先预先渲染或服务端提供正文，避免先下载完整 Markdown 解析器后才出现文字。最终方案由技术设计验证；私密访问不得为追求静态性能而绕开保护。

初始预算：普通公开文章首屏必要 JavaScript 目标不超过 80 KiB gzip，首屏必要传输资源目标不超过 800 KiB；不包括用户主动放大的原图与后续懒加载资源。预算含实际加载的字体；例外需记录页面、理由与测量结果，不能删内容凑数。

LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1 为上线后的体验目标；有足够真实访问样本才评估移动/桌面各自第 75 百分位。上线前按固定设备/网络进行实验测量，不将一次跑分当作真实用户百分位。[指标定义](https://web.dev/articles/vitals)

图片预留位置、按屏幕给合适尺寸；首屏关键图不盲目懒加载。持续滚动无明显卡顿，动画不持续引发重排；以记录中的设备/场景测量，而非宣称所有设备固定帧率。

### 12.2 可访问性

目标遵循 WCAG 2.2 AA 中适用要求：语义结构、可见焦点、键盘路径、可读对比、替代文本和减少动态效果。通过具体检查报告证明，不宣称已取得认证。普通内容在 320 CSS px 等效宽度重排，确需二维布局的内容局部处理。[重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow)

### 12.3 兼容范围

主要验收：用户实际使用的 iPhone Safari、桌面 Safari/Chrome；辅助验证：当前选定的 Chromium/WebKit 自动化环境。具体版本在 M1 记录，至少涵盖当前使用版本与一个合理的前一主要版本目标。版本清单未确认前不能宣称全平台支持。

### 12.4 安全与私密边界

- 不向访客发送私密正文再前端过滤；私密附件的直接 URL 同样需要保护。
- 私密搜索与公开索引隔离，分享卡、RSS、sitemap、构建产物、日志与错误页不泄露私密摘要。
- 私密响应采用适当的受保护缓存策略；公开 CDN 缓存不能混入已登录内容。退出、超时与权限变更均验证。
- Markdown 输出禁止执行脚本和危险链接；允许的原始 HTML 范围在 M1 明确。
- 不将密码、访问凭据、原始公司工作材料写入公开源码或测试报告。日志只记录诊断所需信息。

## 13. 样本与测试范围

至少准备 12 条有代表性的合成/已允许材料：技术、生活、随想各 4 条，覆盖公开/私密/草稿、无图/多图、短文/长文。示例标识清楚，不冒充用户真实经历。

另准备一篇约两万中文字的压力长文、一段 200 列字符量级长代码、12 列宽表格、三级嵌套列表、20 张图片的生活记录、长 URL 与损坏附件。记录图片规格与网络条件，避免用空白占位图替代加载测试。

验证视口：320、360、390、430、768、1024、1440 CSS px，另检查中间宽度及横屏。原型已有 Chromium 检查仅是参考，正式实现需重新测试。验收矩阵给出覆盖与证据要求。

## 14. 维护、发布与可迭代性

- 正式开发启动时建立版本控制、明确源码与内容目录和依赖锁定；本次立项不冒充已建立 Git/远程备份。
- 内容与展示可分别变更，内容协议具有版本；兼容性变化有迁移说明与样本验证。
- 每阶段交付对应报告、可查看结果、测试证据、已知问题与下一步；没有证据不标完成。
- 发布前有构建、内容/链接、权限、阅读回归检查；保留上一可用版本和操作说明。
- 备份包含 Markdown、附件、必要配置；不只备份构建后的网页。恢复演练验证路径与图片完整。
- 主题、排版、响应式和动效有统一参数，避免按文章堆补丁或维护多份手机专用正文。
- 小修复进入补丁版本；新功能进入小版本；破坏内容兼容性的变更必须有迁移说明。

## 15. 阶段与资源

建议基线为立项后约 20 个有效工作日，按一个持续投入的开发能力估算，用户在阶段节点查看结果。不是承诺后台会自动持续运行，也不假定用户自己全职投入。

阶段：M0 立项 → M1 排版/响应式/动效样张与技术决策 → M2 内容和权限基础 → M3 完整阅读展示 → M4 质量与真机 → M5 发布与维护移交。具体日期、产物与门槛见路线图。

不默认新增付费服务或采购工具。域名、托管和鉴权如需付费，技术阶段提供候选成本与选择依据；未提供预算时不编造固定月费。

## 17. 风险与应对

| 风险 | 后果 | 控制方式 |
| --- | --- | --- |
| 只确认整张设计图 | 代码落地失去质感 | M1 先交真实中文样张、多宽度和动效状态，不直接扩全部页面 |
| 手写字体与纹理过量 | 慢加载、难阅读、变成拟物装饰 | 限定使用角色，纯色/系统字体可降级，记录字体授权与体积 |
| 私密能力晚接入 | 搜索、附件与缓存返工 | M1 决策、M2 建立负向测试；不是最后贴登录页 |
| 手机仅缩窗口验收 | Safari 真实问题遗留 | 真机列为正式发布门槛，缺证据就不标真机通过 |
| 无限制追加功能/主题 | MVP 不可控 | 固定 P0 与变更单，新增需求评估替换或延期 |
| 多 Agent 同时修改 | 决策丢失、源码和报告冲突 | 独立交付，单一汇总者合并，共享索引最后读取再更新 |
| 纸面排期被当自动执行 | 错误预期 | 每次执行更新实际状态与预测，不声称无人值守自动推进 |
