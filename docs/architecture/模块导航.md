# 模块导航

本文件按业务概念定位实现入口与边界测试，减少维护者和 AI 的全仓扫描。任务状态与 owner 只看[中央任务台账](../collaboration/board.json)，实际进度只看[项目进度](../project/项目进度.md)。

## 1. 先改哪里

先确定业务概念，再阅读对应入口和最近调用方；不要从 Next 路由开始逐层翻找全部实现。

| 要修改的概念 | 实现入口 | 边界与说明 |
| --- | --- | --- |
| 公开记录读取 | [public-api.ts](../../packages/content/src/public-api.ts) | 固定公开 API、公开响应解析和错误映射；页面路由只负责组合 |
| 主人 SSR 读取 | [owner-api.ts](../../packages/content/src/owner-api.ts)、[桌面组合根](../../apps/site/src/server/owner-api.ts)、[H5 组合根](../../apps/h5/src/server/owner-api.ts) | 共享模块拥有固定会话转发、owner 契约与 CSRF；组合根只读取 Next Cookie |
| 浏览器搜索 | [search-api.ts](../../packages/content/src/search-api.ts)、[search-state.ts](../../packages/content/src/search-state.ts)、[search-contract.ts](../../packages/content/src/search-contract.ts) | API 传输、搜索状态和搜索响应契约分开定位；授权仍在 Nest |
| API 线协议 | [contracts/index.ts](../../packages/contracts/src/index.ts)、[API v1](contracts/api-v1.md) | 稳定类型、运行时解析与 fixtures；公开和 owner 使用不同响应入口 |
| 内容管理界面 | [content-manager.tsx](../../packages/content/src/management/content-manager.tsx) | 桌面与 H5 共用导入、预览与管理界面；各端路由负责主人会话 |
| 内容发布与维护 | [content-management.service.ts](../../apps/api/src/modules/content-management/content-management.service.ts)、[content-management.controller.ts](../../apps/api/src/modules/content-management/content-management.controller.ts) | 上传预览、发布、回滚、导出与别名解析；不在 Next 复制维护逻辑 |
| 桌面阅读 | [reader-article.tsx](../../apps/site/src/features/reader/reader-article.tsx)、[reader-model.ts](../../apps/site/src/features/reader/reader-model.ts)、[reader-interactions.ts](../../packages/content/src/reader/reader-interactions.ts) | 文章组合、纯阅读模型和浏览器交互分别修改 |
| H5 阅读 | [mobile-reader.tsx](../../apps/h5/src/components/mobile-reader.tsx)、[reader-enhancements.tsx](../../apps/h5/src/components/reader-enhancements.tsx) | 移动阅读组合与正文增强；共享控件优先看 `packages/ui` |
| 双端共享 UI | [packages/ui/index.ts](../../packages/ui/src/index.ts)、[reading-preferences.ts](../../packages/ui/src/reading-preferences.ts) | 只放真实共享的展示组件和阅读偏好，不放 API 或页面业务流程 |

新增功能先判断属于哪一行。只有跨概念变更才继续阅读[技术架构](技术选型与研发路径.md)和相关 ADR，避免把路由、传输、权限和展示混在一次修改中。

## 2. 依赖方向

```text
apps/site ─┐
apps/h5  ──┼─→ packages/content ─→ packages/contracts
           │          └──────────→ packages/config
           ├─→ packages/ui
           └─→ packages/contracts / packages/config

apps/api ────→ packages/contracts / packages/config
```

- `apps/*` 可以依赖 `packages/*`，包不得反向依赖应用；前端不得导入 Nest 源码。
- `content` 是读取、发现、传输与共享内容管理界面的边界，`contracts` 是纯线协议，`ui` 是展示与偏好边界。
- Nest 始终是内容可见性和主人授权权威。TypeScript 类型、SSR 或浏览器过滤都不是权限边界。
- 桌面与 H5 只保留真实框架、路由和交互差异；相同业务规则不各写一份。

## 3. 修改规则

1. 先改拥有业务规则的模块，再调整路由组合；不要在页面里补一份协议解析或权限判断。
2. 公开响应必须使用公开解析入口，owner 响应必须使用 owner 解析入口。两者共享结构校验，不共享“公开”权限语义。
3. 主人 SSR 只允许固定 API 路径、固定 session Cookie 和既定错误映射；不要开放任意目标、请求头或 Cookie 转发。
4. 依赖注入用于隔离框架、网络或时钟等外部端口，不为纯函数引入 DI 框架，也不新增一行 re-export、通用 utils 或第二套业务 API。
5. 双端出现第三份相同逻辑前，先确认它是否已有共享所属模块；不要仅凭代码行数合并不同权限或交互概念。

## 4. 验证定位

以下命令均在仓库根目录执行，版本以 `package.json` 为准。

| 改动边界 | 首要测试 | 命令 |
| --- | --- | --- |
| 响应契约 | [contracts/index.test.ts](../../packages/contracts/src/index.test.ts) | `pnpm exec tsx --tsconfig apps/api/tsconfig.json --test packages/contracts/src/index.test.ts` |
| 主人 SSR、会话与私密正文 | [ssr-forwarding.integration.test.ts](../../tests/integration/access/ssr-forwarding.integration.test.ts)、[access.integration.test.ts](../../tests/integration/access/access.integration.test.ts) | `pnpm test:integration` |
| 内容发布与回滚 | [content-management.test.ts](../../apps/api/src/modules/content-management/content-management.test.ts) | `pnpm test:content` |
| 搜索传输、状态与授权 | [search-api.test.ts](../../tests/unit/find/search-api.test.ts)、[owner-search.e2e.test.ts](../../tests/e2e/find/owner-search.e2e.test.ts) | `pnpm test:unit`、`pnpm test:integration` |
| 桌面阅读与完整公开链路 | [reader-interactions.test.ts](../../tests/unit/reader/reader-interactions.test.ts)、[demo.browser.mjs](../../tests/e2e/acceptance/demo.browser.mjs) | `pnpm test:unit`、`pnpm test:browser` |
| H5 阅读与移动交互 | [mobile.browser.mjs](../../tests/e2e/h5/mobile.browser.mjs) | `pnpm test:h5` |

跨端变更至少运行 `pnpm lint`、`pnpm typecheck` 和对应边界测试；完整交接前运行全量门禁。浏览器、合成身份和 Chromium 视口证据不能替代真实 iPhone、生产身份或上线验收。
