# ADR-0003：CI/CD与发布治理

- 日期：2026-10-30。
- 状态：accepted（本轮架构实施基线）；工作流、宿主和权限尚未接入。
- 用户要求：建立完整好用的CI/CD，交由其他Agent实施。

## 决定

基于已有GitHub仓库采用GitHub Actions：PR提供无生产凭据检查；受信main提交构建并记录不可变site/api镜像digest；测试环境验证后，按明确发布授权将同一对产物晋级生产；回滚使用已通过验证的发布清单。pnpm workspace优先，暂不引入额外任务编排平台。

CI不运行真实私密材料；内容、身份、附件与缓存负向检查必须进入流水线。发布并发按环境串行，生产切换中的作业不得随意取消。正式首次发布前完成iPhone真机和恢复演练。

## 权限与外部条件

默认生产发布为受控手动晋级，不是每次merge自动上线。优先用仓库环境保护规则，必须先核对可见性、套餐和所需规则是否可用；不能假设私人仓库免费拥有审批功能。不可用时使用仅发布负责人可触发的外部发布入口/凭据，默认关闭自动生产部署；普通workflow_dispatch不自动等同强审批或权限隔离。

本轮不配置GitHub账户规则、Secrets、镜像仓库、域名或主机；不自动向其他Agent发消息。外部接入按用户现有授权和实际条件执行。

## 代价与验证

需要维护工作流、容器、版本清单和运行手册；初期整体发布简化兼容性，避免过早按路径跳过关键检查。CICD-001交付CI及测试部署证据，RELEASE-001在生产条件具备后演练晋级/失败/回滚/恢复；详细验收见[CI/CD建设方案](../CI-CD与运维建设方案.md)。

备选：纯手动发布不能满足可重复性；另建自托管CI平台增加个人运维成本；均不作为初期方案。若GitHub套餐/网络/镜像访问限制阻塞，记录宿主证据再修订实现，不绕过检查。
