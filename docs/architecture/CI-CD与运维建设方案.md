# CI/CD与运维建设方案

更新：2026-10-30。状态：研发建设基线，尚无已运行的应用流水线或生产环境。对应[ADR-0003](decisions/ADR-0003-CI-CD与发布治理.md)和[正式验收矩阵](../product/验收矩阵-v1.0.md)。本文的门槛是实施要求，不是测试结果。

## 1. 想达到的日常体验

开发者推送PR后自动获得可读的检查结果；main上通过检查的提交可构建和在受控测试环境验证；发布负责人选择已经验证的版本晋级生产。失败保留旧可用版本，能明确知道失败环节、当前服务版本和如何恢复。修改公开Markdown走同样的内容校验与发布；真实私密内容有独立受保护更新/备份流程。

CI从ENGINE-001之后接入，和功能开发并行，不拖到M5。开发没有服务器也能先完成安装、构建、双服务容器、合成内容和E2E验证；生产部署部分可以因外部条件未具备而保持关闭，不伪造成功。

## 2. 环境与数据隔离

| 环境 | 数据与身份 | 凭据 | 生命周期与用途 |
| --- | --- | --- | --- |
| local | 合成公开/私密样本，测试主人 | 本地非生产配置 | 日常开发，私密样本也不冒充真人资料 |
| PR CI | 固定fixture和合成canary | 不提供生产/主机/发布凭据 | 临时运行双服务，执行关键负例，结束清理 |
| staging | 与候选版本一致的公开快照、合成私密样本和独立测试身份 | 仅测试环境权限 | 受信main发布；可先采用临时容器环境，持久域名待宿主落实 |
| production | 明确公开集合、受保护真实私密快照和主人身份 | 单独注入、最小权限 | 实际授权后启用；禁止复用测试会话/密钥 |

测试环境与生产不共享真实私密卷、会话库、域名Cookie或写入凭据。公开预览不等于可以开放测试登录。PR图像/录像/日志只用合成材料，禁止把真实私密正文作为CI上传附件。代码仓库私有也不改变这个边界。

## 3. 推荐工作流与触发

以下为CICD-001需创建的目标文件名，目前尚未创建。

| 文件 | 触发 | 主要动作 | 成功证据 |
| --- | --- | --- | --- |
| ci.yml | pull_request、main push；需要merge queue时另加对应触发 | 安装、静态检查、测试、构建、产物隐私扫描、聚合检查 | 一个稳定的required状态、失败定位、测试报告 |
| release-build.yml | 受信main的检查成功后 | 核验SHA与来源，构建两镜像，测试镜像，生成发布清单，推送仓库 | digest、源码SHA、契约/内容版本和构建记录 |
| deploy-staging.yml | 受信构建成功 | 按digest拉取，配置预检，启动、ready、冒烟与授权负例 | 环境地址或临时环境记录、版本与结果 |
| promote-production.yml | 发布负责人选择已通过staging的release ID | 核对权限/证据/兼容性、备份前置、晋级、验证 | 生产release ID、前后版本和审计记录 |
| rollback.yml | 受控人工选择允许回退的release ID | 兼容预检、切回完整版本组合、健康与权限复验 | 实际恢复证据，失败则明确停止 |

工作流可用可复用job避免重复，但CI必须在干净环境可独立复现，不能拿另一条流程“曾经绿过”当当前SHA验证。特权workflow_run等事件必须核验原运行属于本仓库受信main与指定SHA，不能盲信PR上传的脚本或artifact。初期也可将检查/构建/测试部署串在同一受信main工作流，减少跨workflow信任面；以上职责不要求强拆五份YAML。

## 4. PR检查与合并门槛

| 检查组 | 实施要求 | 阻止合并的情况 |
| --- | --- | --- |
| repo | 现有Python文档/任务校验，基础协作工具测试，内容元数据/链接/附件检查 | 坏链接、索引过期、缺文件、任务依赖错误 |
| static | 锁定Node/pnpm、frozen lockfile安装、lint、TypeScript | 锁文件漂移、前后端契约冲突、前端引入服务端代码 |
| unit/contract | 内容解析、清洗、ID/slug、类型与接口兼容，重点业务规则 | 恶意Markdown、路径逃逸、schema无效、不兼容接口 |
| integration | Nest真实模块与临时存储，合成登录/退出/过期、附件、搜索、缓存 | 未授权返回私密字节，空结果掩盖错误 |
| build | site/api生产构建与运行冒烟，HTML中有正文 | 构建失败、空壳正文、缺共享包或静态资源 |
| privacy | 公共产物、客户端包、HTML/RSC响应、搜索、元数据、错误与日志的私密canary检查 | 访客可取得私密标题/正文/附件/索引片段 |
| e2e | 合成三类文章，列表/搜索/阅读/主人路径、键盘和移动视口 | 核心路径失败、全页溢出、失焦/残留滚动锁 |

canary可以存在于测试源数据及Nest测试环境的受保护数据中；扫描对象为可公开产物/访客响应等出口，不将“fixture本身含canary”误判成泄露。测试报告不得上传包含真实身份的响应。

早期应用规模小，默认全量检查。即使只改docs，也必须产生稳定的聚合required状态；避免路径过滤导致required check永远pending。后续若做变更影响分析，共享包、锁文件、构建配置、content变更必须触发相关前后端检查，不能只按apps子目录判断。

单元测试验证有意义的规则与边界，不要求每个展示组件写镜像式测试或追逐覆盖率。设计评审和真实iPhone Safari不被自动截图替代；自动化视口至少按验收矩阵覆盖320、360、390、430、768、1024、1440。完整设备证据在M4/M5门槛收集。

首次基线记录PR总耗时、安装/构建/测试分段耗时和缓存命中；持续优化最慢步骤，不在实测前承诺固定耗时。偶发失败允许定位后重跑，禁止无限自动重试把失败刷绿。

## 5. 构建一次与发布清单

同一受信SHA构建site/api镜像，以digest部署；可读SHA标签只做检索，不使用可变latest作为唯一回滚凭据。测试环境验证后的相同digest晋级生产，不在生产机重新拉源码构建。两镜像的操作系统架构必须与宿主相符，不能默认笔记本产物可直接用于Linux服务器。

release manifest至少包含：release ID、Git SHA、site/api digest、契约版本、公开contentRevision、测试运行链接、构建/批准时间、目标架构、必要配置schema与迁移标识。私密快照引用在受保护的部署记录中，公开manifest不能包含私密材料路径或凭据。

为保证同产物晋级：浏览器API采用同域相对路径；内部API地址和会话配置用服务端运行时变量；不得将staging地址、真实数据或密钥编译进NEXT_PUBLIC变量。Next构建期冻结的公开值必须列入清单；若某环境确需不同编译产物，视为新的release并重新测试，不能冒充同产物晋级。

Next standalone验证共享包追踪、运行目录、public与静态产物复制。容器采用最小运行依赖和非root用户；构建上下文排除private、凭据、Git内部目录、历史设计大图和无关文件。Nest镜像只允许带入显式公开快照；Next镜像不带私密源。镜像/依赖扫描的可修复高风险问题先阻断，不能简单设为continue-on-error；例外有责任人、影响与期限。

## 6. 部署序列、并发与失败处理

推荐初期单机Compose，不强制零停机。staging和production分开配置、端口、卷与发布记录；服务器资源不足时staging先使用临时CI环境，不为保留环境先行购买资源。

一次发布按下列顺序实施：

1. 核对release来自受信提交、CI/staging通过、正式发布门槛或明确的预览范围满足，并具备目标环境发布授权。
2. 获取环境级发布锁，读取当前release，检查磁盘/配置/依赖/卷权限和可用回滚组合；状态迁移前完成可恢复备份。
3. 拉取两镜像digest并验证，准备内容快照与兼容迁移。不要先停止旧服务再发现镜像不存在。
4. 按前后兼容顺序更新（通常兼容API先、site后），明确维护窗口；ready检查不能只看进程存在，Compose启动成功也不算业务就绪。
5. 验证公开文章HTML、静态资源、API契约、匿名拒绝、测试主人会话与附件边界；生产检查只输出脱敏结果，不抓取主人正文进入日志。
6. 通过后写当前release与版本记录，清理确认可丢弃的缓存；保留至少一个已验证可回滚版本，记录发布耗时与结果。
7. 失败时停止后续步骤；若已切换且兼容允许，恢复前一个完整release组合并复验。恢复失败要明确报告，需要人工处理；不能仅返回绿色“已回滚”。

PR检查可取消旧提交的运行。生产部署、内容切换、迁移与回滚按同一环境串行，不能在迁移中途被新push取消；所有入口共用宿主锁，避免两个工作流或人工命令同时修改状态。GitHub concurrency不保证业务上的严格先进先出，切换前再次校验release是否仍为预期版本。有关机制见[官方并发说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)。

若以后需要低停机，另做双槽/蓝绿切换、共享状态兼容与资源预算验证，不在本期文档直接承诺。

## 7. 权限与仓库保护

GitHub工作流默认只读权限；仅发布镜像job拥有仓库写入权限，仅部署job接触目标环境凭据。优先短期身份/OIDC（宿主支持时），否则专用最小权限凭据，注明轮换和撤销办法；不复用个人全权限SSH密钥。第三方Action固定完整提交SHA并维护升级记录，不执行PR提供的任意发布脚本。缓存中不存会话、私密数据或凭据；不信任来自不受信PR的产物进入特权流程。参考[GitHub安全使用说明](https://docs.github.com/en/actions/reference/security/secure-use)。

main建议PR合并、稳定required CI、禁止强推与直接覆盖，按真实团队配置审核；一个人维护不虚构必须有第二位审批者。用户/Agent的代码协作权限不自动带来生产权限。当前不修改仓库规则。

GitHub环境与审批功能受仓库可见性/套餐限制，尤其私有仓库的required reviewers不可默认可用。CICD-001先记录实际能力；若可用则用环境保护规则，若不可用，生产自动部署保持关闭，采用由发布负责人控制凭据的外部发布入口或其他经过验证的权限隔离。普通手动触发按钮并不天然等同审批关卡。不要为开通这些规则自动购买套餐。[GitHub环境能力说明](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)

## 8. 备份、恢复与内容更新

GitHub源码不是私密备份，镜像也不是全部数据备份。RELEASE-001应列出公开与私密原文/附件、身份/会话持久数据、配置清单与密钥恢复方式；缓存与搜索索引可重建。备份加密、密钥分开保管，至少有与主机故障隔离的副本；备份目的地、保留周期与成本待实际环境决定。

制定日常自动备份与危险变更前备份；建议内容数据初始RPO目标24小时、RTO目标4小时，均为待用户接受并由恢复演练校验的运行目标，不是已达成SLA。真实私密备份不得上传普通Actions artifact或普通代码仓库。

至少完成一次从备份恢复到隔离空环境，核验内容ID/附件校验和/访问权限/登录行为，并记录耗时。回滚应用镜像与恢复数据是不同动作：兼容数据库迁移采取先扩展后收缩；无法安全回退schema时采用向前修复或经批准的恢复，不能自动破坏性降级数据库。会话恢复若会复活已撤销状态，必须作废会话或有明确撤销策略。

公开内容变更可以作为普通PR；公开转私密必须撤销旧公开缓存与索引，并对回滚快照加可见性检查。私密内容维护由受保护流程生成新快照/索引后切换，失败保留原可用快照。源码、公开内容和私密内容版本彼此可追溯，但不把真实私密源塞入构建以方便版本管理。

## 9. 运行可观测性与维护节奏

最低运行信息：当前release/内容修订、live/ready、HTTP错误率与响应耗时、容器重启、CPU/内存/磁盘、证书到期、备份最近成功时间。日志结构化且脱敏、定期轮转，避免磁盘被错误循环耗尽。通知只在服务异常、连续失败、备份超时等可行动事件触发；具体渠道等待用户指定，不自动发送外部消息。

按月检查依赖与镜像更新，安全修复按风险提前处理；升级走相同PR和staging验证，定期检查Node及框架支持周期。每次发布记录变更/验证/已知问题；定期抽样恢复和核对备份完整性。机房/网络/地域限制与数据保管责任在宿主决定时补充，不预设某云平台。

ops目标手册：环境与配置字典、首次部署、日常发布、公开/私密内容更新、回滚、备份恢复、日志与故障、版本升级。每份手册有前提、可复制命令、预期输出、失败处理、最后验证日期；未执行的步骤标待验证。

## 10. CICD-001与RELEASE-001验收证据

| 场景 | 责任任务 | 必须保留的证据 |
| --- | --- | --- |
| 干净安装、锁文件与共享包变更 | CICD-001 | 无人工补步骤通过的运行记录 |
| 测试失败/构建失败/私密canary泄露 | CICD-001 | 作业红灯并阻断后续发布；修复后复测 |
| 无生产凭据的PR运行 | CICD-001 | 权限配置检查与fork/不受信来源隔离验证，不打印真实secret |
| 同一对digest从测试晋级 | CICD-001 / RELEASE-001 | 清单、镜像版本、环境核验与实际晋级记录 |
| staging无健康/无身份依赖 | CICD-001 | 明确失败，不覆盖旧可用状态 |
| 两次并发发布/旧候选版本 | CICD-001 | 同环境无重叠切换、过期候选被拒绝或明确人工选择 |
| 生产失败后回滚 | RELEASE-001 | 演练记录、完整版本组合和权限复验；不在真实生产注入未经授权故障 |
| 数据恢复与会话撤销 | RELEASE-001 | 隔离空环境恢复、附件校验、登录/注销与实测耗时 |
| 正式发布 | QA-001 / RELEASE-001 | AC-01–18及NFR证据、iPhone真机、S0/S1为零、外部条件和发布授权 |

自动化不能代替阶段报告。工作流存在、YAML通过解析、CI实际成功、测试部署成功与生产发布成功必须分开记录。未拿到主机/账号时交付可审查配置和本地/CI证明，不能标记生产已上线。
