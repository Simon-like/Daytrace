## 分工顺序

| 波次 | 任务 | 写入职责与交付 | 依赖与集成 |
| --- | --- | --- | --- |
| A | ARCH-001 | experiments/ARCH-001：固定Next/Nest路线的可运行样本、版本兼容、完整HTML、JS/字体/图片预算、容器与共享包可部署性 | 不改正式应用、不选另一框架；交接推荐精确版本 |
| A | CONTENT-001 | docs/architecture/contracts与模板：Markdown字段、可见性、slug/ID/附件、接口/错误与修订协议、迁移样本 | packages/contracts由ENGINE按协议实现，避免并发改共享源码 |
| A | SECURITY-001 | docs/architecture/security与独立实验：登录/会话/主人白名单、Cookie、CSRF、附件/搜索/缓存边界 | 提供成熟身份方案、成本前提与负向证据，不把模拟身份当生产 |
| B | ENGINE-001 | apps/site、apps/api、packages与根配置：唯一正式双应用、统一命令、共享契约、公开Markdown纵向切片、配置启动校验 | 串行维护路由/布局/公共样式/锁文件，先合并A波结论；不创建发布工作流 |
| C | READER-001 | site reader：技术/菜谱/随想正文、目录、复制、图片、动效与响应式 | 不另做解析/鉴权；接口需求先交接 |
| C | FIND-001 | site records/search，api search：首页/分类/筛选/公开检索，主人检索必须消费已定义授权策略 | 不改auth/assets；权限策略由ACCESS提供，缺实现先用fixture联调再真实验证 |
| C | ACCESS-001 | site owner/server，api auth/assets：主人访问、SSR会话转发、附件/退出/缓存隔离 | site/server业务仅适配，权威权限在Nest；不得复制第二套内容模块 |
| C | CICD-001 | .github、ops/cicd、scripts/ci、tests/cicd：PR检查、可信镜像、发布清单、临时/持久测试部署、受控生产入口 | 不改业务或锁文件；需依赖/脚本变更交给集成者；生产未接入仍可交付受控模板 |
| D | QA-001 | 正式验收矩阵、视口/浏览器与iPhone、权限负向、失败与性能证据 | reader/find/access/cicd完成后执行；不继承原型“通过” |
| E | RELEASE-001 | 实际外部接入、运行手册、受控发布、回滚/恢复演练和移交 | 首次生产需实际条件/授权；工作流变更由集成者划给本任务，不能按旧范围越界 |

各Agent的允许写入路径在board，表格仅解释职责。ENGINE交付基础content模块；后续content公用逻辑/共享契约变化由集成者串行处理，不让FIND或ACCESS为图方便重写。QA不得以测试代码反向修改业务。需要新任务时由协调者分配明确范围与依赖。

## 最小任务接力方式

给Agent以下文字并填入真实任务ID即可，不必复制全部历史聊天：

> 在Daytrace仓库执行指定任务。先读AGENTS.md、docs/context/当前工作上下文.md、docs/architecture/研发交接与任务编排.md及对应任务卡。技术方向Next.js + NestJS + pnpm workspace已确认，禁止重新选框架。先确认中央board依赖与认领，再基于最新主分支使用独立分支/worktree，仅修改允许路径；共享变更交集成者。交付代码、运行说明、真实验证、未验证项、协调交接单与PR；不能把本地测试冒充部署或真机验收，不启动真实生产或导入私密数据。

## 中央队列、worktree与PR

中央checkout负责认领；worktree不操作自己的台账副本。现有脚本是本地文件锁，不是跨设备协调服务；如果其他Agent在另一台设备/托管沙箱工作，必须由单一协调者在中央board分配，Agent通过PR/交接反馈，不能各自“认领成功”后覆盖台账。

从最新可访问的origin/main创建agent/任务ID/短名分支。若离线或远端不可用，记录所基于提交并在集成前重放最新变更。不要使用reset/强推消除他人修改。PR描述提供任务ID、契约影响、实际验证、未验证、数据/配置变化和回滚影响。main的实际保护规则以仓库配置为准，不把建议当已配置。

当其他任务更新共享锁文件，先让集成者完成该次变更再同步分支；不并发安装新框架。提交单元按职责保持可评审；依赖新增说明体积、运行时和必要性，不因图标/动效引入完整UI系统。

## 阶段报告与完成定义

任务done：交付存在、命令可复现、相关测试通过、已知问题记录、有交接与真实评审。自检可记录，但不得称独立评审；board的done不自动等于已合并/已部署，交接必须注明对应提交/PR及集成状态。集成者维护权威文档、目录、项目记忆和阶段进度。

M1完成还需A波验证、版本与协议/身份前提。M2–M5仍需正式实现和验收。QA与发布退出标准按产品矩阵，不为了“全绿”删减断言或用空壳脚本替代检查。
