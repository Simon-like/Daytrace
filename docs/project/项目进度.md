## 后续开发基准

- 后续只使用`dev`日常开发分支与`main`稳定集成分支。每个新任务从最新`origin/dev`开始，成果先提交`dev`；`main`只通过明确的`dev → main`合并更新，不再创建agent任务分支。
- 每轮实质改动完成并验证后都要按功能／修复／文档边界独立commit并推送`dev`，不把多轮无关改动堆在工作区或一个提交；提交不等于合并`main`、部署或验收。
- 工程锁定 Node.js 24.18.0、pnpm 11.23.0，正式依赖基线为 Next.js 16.4.3、NestJS 12.3.2、React 19.3.1；以根 `.nvmrc`、`.node-version`、`package.json` 和应用 manifest 为准。
- 保持 Next.js + NestJS + TypeScript + pnpm workspace 及现有内容／权限边界。移动端可以拥有独立页面和交互，但不复制第二套业务 API；共享控件能力以可选、向后兼容的方式演进。
- 所有新工作先由协调者建立任务卡并认领；共享路由、契约、依赖与锁文件由集成者串行处理。文档完成、模块 done、本地 Demo、正式 QA 和生产发布是不同门槛。
