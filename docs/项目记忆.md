# 项目记忆

更新日期：2026-11-02。用途：接手摘要与源文档定位，不复制全部需求、任务状态或历史报告。

## 用户确认的方向

- 个人知识与生活站点，沉淀技术实践、生活经验和随想认知；希望回看自己的变化，重温勉励自己的话。
- 技术记录要留下真实问题拆解、入口、排查与验证路径，而不是只生成通用百科；生活菜谱区分实际做法与教程；感想保留原话。
- 一期展示与阅读优先；手机网页尤其iPhone的排版、响应式与流畅度是核心；电脑整理素材，手机采集以后扩展。
- Markdown为主要流通载体；材料不足先保存，允许以后补充；不做站内编辑器、原生App或复杂Agent。
- 公开站点同时支持私密记录，不能靠前端隐藏实现保护。
- 主题收敛到D/D²私人档案感，必须保留手写装饰，避免E大面积撞色；不继续横向增加主题。
- 用户不想读长工具清单，Agent负责筛选，用户主要看设计与实际结果。
- 希望多Agent贡献并相互学习，项目要有阶段报告、可控进度、可维护的迭代。
- 最新反馈：七模块页面稿“先这样”。随后明确本轮只定文档结构与上下文；技术栈后来已明确为React/Next.js + NestJS + monorepo，见最新ADR；当前由其他Agent按任务接手研发。

用户最新授权验收Kimi并继续开发到成品Demo。本轮已集成Kimi的READER/FIND/ACCESS/CICD四个提交，ENGINE早已建立正式site/api与contracts/config，不能再按旧“未创建工程”执行。

## 关键边界

- “日常有迹”是暂名；图片/文章/日期为设计示例。THEME-009提供秩序与质感，THEME-004提供手写语言；其他Agent原型及测试不与正式实现混淆。
- MODULES-001原图约2.86MB，尚未完成生产级多尺寸处理与资源预算；不能把本地速度当线上成绩。
- 约20有效工作日只是参考基线，实际节点按依赖更新，不会到日期自动完成或自动运行。
- 缺失可见性不公开；精确字段、字体/色值/动画参数、身份提供商和托管/成本需按对应决定锁定。
- docs记录产品怎么建；knowledge记录可复用研发认识；content记录主人想沉淀的个人内容，三者不能混成一个自动发布目录。
- 中央任务队列原子认领；独立交付、单一集成者合并共享文件。台账不等于文件权限，跨设备不是分布式锁。
- 其他Agent不自动得到本聊天或最新文件；共享记忆仅供接入同一服务的工具检索，源文件优先。
