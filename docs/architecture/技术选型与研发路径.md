# 全栈技术架构与研发路径

更新：2026-10-30。状态：用户确认技术方向；工程、版本与部署尚未实现/验证。本文件取代原先未讨论的Astro优先候选，不改变既有产品范围。决策依据见[ADR-0002](decisions/ADR-0002-技术路线候选.md)。

## 1. 目标与决定层次

用户确认：React生态采用Next.js，后端NestJS，monorepo管理；后续要有完整好用的CI/CD，由其他Agent完成开发。本轮只形成研发与交接基线，不生成脚手架、不安装依赖、不运行其他Agent、不发布。

本轮架构实施基线：全栈TypeScript、pnpm workspace、Next.js App Router、Nest模块化单体、同域入口、接口版本化；基础CI采用GitHub Actions。Docker容器、单机反向代理与Compose为初始交付建议，须验证宿主和预算后落地。它们不是用户逐项确认的托管采购决定。

尚待实施任务锁定：Node/React/Next/Nest/pnpm精确兼容版本、Markdown工具链、身份提供商与会话存储、服务器/镜像仓库/域名/费用。采用各项目仍受支持且互相兼容的版本，记录选择日期与实际测试；不在文档编造“当前最新版”。

产品优先级保持：手机阅读、D/D²与手写、标准Markdown、公开与私密、技术/菜谱/随想；站内编辑、复杂Agent、原生App仍在后续。

## 2. 系统边界与请求路径

```text
浏览器（同一域名，HTTPS）
  └─ 反向代理
       ├─ 页面 /、/records/...、/owner/... → Next.js site
       ├─ /api/v1/...                    → NestJS api
       └─ 仅明确公开的静态资源             → 静态资源服务

Next服务端 ── 内部API地址 ── NestJS
                              ├─ content：Markdown解析、校验、版本与查询
                              ├─ auth：主人身份、会话与授权
                              ├─ assets：公开/私密附件访问
                              └─ search：公开/主人索引
                                       ↓
                 公开内容快照 / 独立私密只读快照 / 派生索引
```

这描述目标结构，不代表服务已经存在。后台保持一个Nest应用，用模块分工；不因多Agent而引入微服务或微前端。

| 层 | 负责 | 明确约束 |
| --- | --- | --- |
| Next页面层 | 路由、服务端正文、元数据、响应式、交互、目录和照片查看 | 不直接扫描私密目录；业务API不重复放到Next；Server Components也不是权限边界 |
| Next服务端适配 | 服务端API客户端、请求关联、受控会话转发、错误状态转换 | 只能访问已定义接口；不接收任意代理目标；不能凭“内网”跳过授权 |
| Nest业务层 | 内容验证与查询、权限、附件和搜索、后续导入 | 每个私密出口执行主人授权；错误/日志不输出正文或凭据 |
| 共享契约 | 请求/响应结构、运行时校验规则、版本约束 | 不包含Nest装饰器、数据库实体、Node文件读取或任何密钥 |
| 数据层 | Markdown与附件原件、稳定ID、内容修订、派生索引 | 正文不绑定数据库私有格式；索引可重建，原文/附件须备份 |

## 3. 仓库与依赖方向

```text
apps/site/                       @daytrace/site，Next.js
  src/app/                       路由与布局，集成者维护
  src/features/{records,reader,search,owner}/
  src/server/                    仅服务端API适配，禁止业务权限副本
apps/api/                        @daytrace/api，NestJS
  src/modules/{content,auth,assets,search}/
  src/common/                    请求关联、统一错误等基础设施
packages/contracts/              @daytrace/contracts，跨端纯契约
packages/config/                 @daytrace/config，共享工程配置
content/{public,private,fixtures}/ 既有内容边界；private不进入普通Git/镜像
ops/                             部署、运行手册、发布及恢复证据
.github/workflows/               待CICD-001实现
```

只为前后端已有的两个消费者建立contracts/config，暂不拆UI包、工具大杂烩包或Agent运行时。依赖方向为site/api → contracts/config；包不得反向依赖apps，前端不得导入api源码。包间显式workspace引用；一个pnpm锁文件，运行时和包管理版本固定。pnpm本身支持这些工作区关系，见[官方workspace文档](https://pnpm.io/workspaces)。

ENGINE-001建立统一命令契约：`pnpm dev`、`lint`、`typecheck`、`test:unit`、`test:integration`、`build`、`test:e2e`；内容校验与文档校验单列命令。此处是交付要求，命令尚不存在，不能现在报告可运行。默认dev同时启动site/api，文档注明端口、配置和停止方式。

## 4. 页面渲染与性能

以App Router的服务端渲染交付首屏正文；菜单、复制、筛选等局部才进入客户端组件。公开页不强依赖构建时在线API：第一条纵向切片先验证运行时SSR和完整HTML，再根据测量决定公开页预渲染/缓存，不一开始耦合Next构建与Nest启动。

公开响应只来自明确公开集合，不读取请求身份后拼入主人记录。需要预渲染时，仅输入显式公开的、可校验的内容快照。私密页与主人首页按请求读取，无共享静态生成、ISR或公共缓存；具体Next缓存控制按锁定版本实现并用双会话负向测试验证，不能只依靠URL前缀或某个默认值。

服务端渲染不自动等于加载快。保留[PRD](../product/PRD-v1.0.md)初始预算：普通公开文章必要JS目标80 KiB gzip、首屏传输800 KiB。ARCH-001测量Next基线及字体/图片；超出则给出拆分与优化方案或明确评审的预算例外，不悄悄提高预算或宣称Next必然满足。LCP/INP/CLS目标继续按PRD区分实验与真实用户数据。

普通Markdown保持可迁移；Nest侧将原文解析为结构化标题/目录与清洗后的HTML/代码高亮结果，Next负责展示，浏览器不下载整套解析器。禁止任意MDX执行、危险HTML/URL和附件路径逃逸；解析与清洗的库、允许元素和语言回退由CONTENT/SECURITY任务实测固定。共享展示样式在site，不能把整份原型当正式实现。

正文图片保留尺寸，采用合理派生尺寸与懒加载；私密图不得进入Next公开图片优化缓存。私密附件走授权接口返回，公共CDN不代理此类响应；后续若选签名URL，另写有效期与撤销测试。

## 5. 接口、身份与兼容

接口方向为`/api/v1`：公开列表/详情/搜索只返回显式公开内容；主人列表/详情/搜索必须授权；附件按资产ID定位，不接受任意磁盘路径。最终字段由CONTENT-001的契约确认，不在前后端分别自拟。

契约至少描述：稳定ID、slug/旧链接、类型、标题、标签、发生/更新日期、状态、可见性、修订与附件引用；HTML与目录来自同次解析。可见性缺失默认不公开，发布仍需显式操作。坏内容返回可定位的校验错误，不能把失败伪装成空列表。生产错误包含稳定错误码和requestId，不回传内部堆栈。

身份建议采用成熟提供商的登录与服务端可撤销会话，主人由明确白名单准入；不开放任意注册。浏览器通过同域`/api/v1/auth/...`建立HttpOnly Cookie，会话和主人权限在Nest验证。Secure/SameSite、登录回跳、CSRF/Origin校验、注销、过期及密钥轮换由SECURITY-001覆盖。身份库、持久化方式和账户成本尚待选定；不假设内存会话能覆盖重启/多实例。

Next的主人SSR只向固定内部API转发必要会话字段，不将Cookie嵌入HTML或客户端配置，不转发到第三方。私密API、主人页面、附件和错误均禁止公共缓存，相关认证响应使用no-store并验证CDN行为。浏览器缓存、退出后已打开页面的处理也需测试；已发送到设备的字节无法仅靠注销召回，不能承诺反向擦除。

接口变更先改共享契约并通过跨端测试。兼容字段先添加、调用方迁移后再移除；schemaVersion/API版本与发布组合留档。前端和API可以独立构建，生产初期按兼容的一对镜像一起发布，避免误以为共享TS即可保证线上兼容。

## 6. Markdown与运行数据

公开正文/附件先以显式公开内容快照交付，镜像允许包含这一集合。私密源、真实身份、凭据不进入构建上下文、镜像层、GitHub日志或测试产物。私密源在宿主受保护位置以只读快照挂载给Nest，Next容器不挂载；对象存储为后续等价适配方案，待托管条件验证。

每次内容更新：校验 → 创建不可变快照 → 重建对应索引 → 验证访问边界 → 切换版本。公开变化可触发发布；私密更新走受保护的内容维护流程，不通过提交真实私密文档触发公开Actions。流程由RELEASE-001演练；一期不新增站内编辑器。

发布清单记录代码提交、两镜像digest、公开contentRevision、契约版本与可恢复的私密快照引用；私密引用不得暴露可推断个人信息。缓存以内容修订区分，不能与原文不同步。公开转私密需要清理旧公开索引/页面/缓存并禁止回滚到再次公开的旧快照；曾经公开的副本无法保证全网消失。

正文暂不强制数据库；会话/身份、未来任务状态是否需要数据库由SECURITY方案决定。若引入数据库，必须补充迁移、持久卷、备份与兼容回滚，不能把正文原件仅存成不可导出的记录。

## 7. 部署与运行方向

初始建议一个站点入口、Next/Nest两个容器，加一个反向代理；同域`/api`路由减少跨域配置。Next/Nest端口只在受控网络暴露。Next支持自行托管，standalone产物在monorepo下需验证共享包追踪与静态资源复制：[自托管](https://nextjs.org/docs/app/guides/self-hosting)、[输出说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)。

状态与应用容器分离，重建容器不丢内容/会话。启动校验配置，缺必要凭据则失败且不打印值。提供不带敏感信息的live/ready检查；API内容快照/会话依赖不可用时不能假装就绪。日志带requestId、版本、耗时与错误码，禁止记录正文、搜索原词、Cookie、Token；必要业务诊断仅用脱敏标识。

CI/CD、环境差异、发布序列、监控和故障恢复详见[CI/CD与运维建设方案](CI-CD与运维建设方案.md)。当前不承诺单机零停机或指定月费。缓存、队列、独立worker、数据库和多实例在真实瓶颈出现后按ADR扩展。

## 9. 重审条件

性能预算无法合理满足、私密数据无法在宿主可靠保存、身份方案需付费且未获接受、Markdown迁移受限或接口边界重复，均需记录问题及最小调整；不静默更换用户已确认的React/Next/Nest方向。版本冻结与生产准备仍需工程证据，方向accepted不等于技术验收完成。
